# Astra 第二轮：文件准备、收集与结果目录

2026-11-13。按 Astra 最后一轮架构建议承接第一轮批量续算，修改通用宿主，不修改独立扩展算法和已安装扩展。

## 已实现

结果与后处理中的“文件与日志”、扩展结果和结果目录均可发起“收集文件到本机”。选择具体产物后，宿主解析 ArtifactRef 并实时读取来源文件的大小、修改时间和实际路径，冻结传输来源。小结果文件默认勾选，大文件由用户按需选择。页面分别显示任务状态、已传大小、错误、暂停、继续收集和下载本机副本。

收集任务保存于工作区 `file-transfers/index.sqlite3`，每项拥有私有 `payload.part`，成功核对后原子发布 `payload`。本机文件按块读取，远端文件用 rsync 复用部分文件，不将大文件塞入 JSON，不重复计算完整源文件哈希。远端别名的连接配置也被固定；来源版本变化、主机连接变化或原目录已清理时不发布副本。原文件和历史路径保持原位。中断后继续同一传输记录，成功结果可按版本复用。

后台一次收集一个文件，控制网络、磁盘与内存使用。传输进程退出后仍保留部分文件；应用重启会从持久化任务恢复。取消后停止收集并保留部分文件。待收集、运行中和失败但可恢复的任务进入既有远端清理引用检查；显式暂停释放来源引用，已完成的本机副本可独立下载。

宿主小文件回传直接调用现有 SSH 通道，去掉外部 Python CLI、本地 socket 绕路及按具体服务器名选择脚本。与独立 CLI 共用原小文件读写和原子发布规则，原 CLI 继续可用。小型 JSON 摘要、普通预览仍保留原 10 MiB 边界；大原始文件通过独立收集任务传输。

本机扩展允许按其清单声明的大小使用远端大输入，同一宿主准备适配器负责取回文件，再交付本机路径给扩展。准备阶段失败时记录准确阶段，可在原分析上“继续准备输入”，复用已经准备好的输入；分析真正启动后不会走这条准备重试路径。远端同主机 staging 沿用现有私有目录复制规则。

扩展响应区分计算、摘要收集和展示状态。程序成功退出而摘要收集失败时，保留退出证据，继续收集原产物；展示失败继续使用原有重建展示入口。可选大产物在独立文件任务中显示各自状态。旧 `state` 字段继续兼容原监控和记录读取。

“数据集”页面现在以结果目录为主要内容，统一列出计算记录、独立扩展、旧后处理、本机分析、保存图表、能带比较与独立副本。计算可直达准确运行；分析可直接查看。失败和正在运行的独立扩展也可定位原分析和恢复动作。原“登记到数据集”改称“保存独立副本”，完成分析自动出现，保存副本为可选动作。旧电子结构 manifest 导入与原绘图文件入口收进可展开区域。

分析历史及图表目录使用 `history-index.sqlite3` 保存项目、来源 attempt、时间和文件版本元数据。详细 JSON 保持权威来源；列表只解析新增或变化的文件，再按项目和来源定位。删掉派生索引可重建，不迁移历史数据。目录筛选、选中详情和刷新继续使用请求身份保护；文件任务轮询复用 `pollSerial`。

## 兼容边界

- 当前工作区约定要求新计算 attempt 仍使用用户项目下 `flows/main/stages/.../attempts/...` 布局，批次/case 对应关系由冻结记录与清单保存；没有改写既有计算目录或迁移历史目录。
- 远端大文件收集需要本机和目标服务器均可使用 rsync。缺失时保留任务并显示可恢复错误；Windows 上的小文件宿主路径继续兼容，大文件需用户已有可用的 rsync。
- 输入准备支持远端来源到本机分析；远端分析沿用现有同主机来源约束。本轮没有扩展跨服务器分析 staging。
- 已取回大文件通过独立下载接口交付，不作为可无限读取的页面 JSON 或自动复制进独立分析快照。保存副本沿用原有有界报告快照合同。
- 只操作合成临时数据，未连接真实服务器、提交科研任务、迁移研究数据、重启正式服务、同步 GitHub 或发布安装包。正常重启工作台后加载新后端入口，页面刷新加载前端。
