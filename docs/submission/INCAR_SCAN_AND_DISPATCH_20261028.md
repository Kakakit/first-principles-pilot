# INCAR 原文列表与节点池提交方式 · 2026-10-28

## 使用

参数迭代的维度类型选择 **INCAR tag**，可搜索参数名或中文名称，也可直接填写自定义 tag。选择“逗号分隔列表”后，每项作为该 tag 的原文值；多个维度作笛卡尔组合，仍限制为 4 维、64 个 case。

| tag | 列表示例 | 生成内容 |
|---|---|---|
| ENCUT | `400, 520, 6e2` | 保留数值原文 |
| ALGO | `Normal, Fast` | 枚举取值 |
| LREAL | `.TRUE., .FALSE.` | 布尔取值 |
| SAXIS | `0 0 1, 1 0 0` | 两个向量，各自作为一个值 |
| MAGMOM | `2*5 2*-5, 2*4 2*-4` | 保留 VASP 重复语法 |
| SYSTEM | `"a,b", "c,d"` | 双引号内的逗号不拆分 |

起点、终点、步长仍可使用；POSCAR 的范围、点数、列表及 U/J、k 网格保持。切换取值方式保留原草稿。INCAR tag 统一大写；重复维度与会覆盖同一 LDAUU/LDAUJ 的组合需修正。每项只接受单行值，不能夹带第二次赋值或注释。

预览展示实际 INCAR 差异，冻结保存该 case 的完整输入；不回写基础节点。复用既有无损 INCAR 解析器和文本覆盖。自定义 tag 给出提示，由使用者确认目标 VASP 版本识别；现有必要文件、结构维度及执行输入检查仍保留。原文传递不表示所有参数组合都具有物理意义。

## 节点池与调度

服务器资源区保留两种方式，新草稿默认 **交给调度器排队**；明确选择与已保存的等待方式均保留：

- **交给调度器排队**：使用明确的 CPU/GPU 请求和本次确认的脚本，不以实时空闲量阻止提交；节点状态只作提示。脚本已有独占要求继续保留。候选节点按本机在途任务数量选择，包括调度器暂未显示的本机回执；两个节点承接四项独立任务时按 1、2、1、2 分配。这里只平衡工作台已知任务，不声称掌握其他用户的实时负载。
- **等待节点空闲后提交**：复用容量诊断和本机占用记录，资源满足才推进，需要工作台持续运行。GPU 沿用整节点等待合同。

扫描的本批在途上限独立于候选节点数量；全局/主机/核数上限继续生效。运行记录、恢复、计算链、普通扫描、能窗扫描及最终提交使用相同策略；改变策略使原资源预览失效。排队模式 GPU 授权内容不随诊断缓存是否存在而变化，MPI 进程数不能超过填写的 CPU 申请。切换策略保留申请数量，由新策略重新生成分配方式和预览。

旧授权缺少策略字段时按原等待方式读取；不回写或重新提交历史任务。依赖步骤、UNKNOWN、重复提交防护及原始调度器错误保持。
