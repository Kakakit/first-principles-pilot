# 服务器与脚本设置、GPU 提交验收

2026-10-08。状态：已实施；本机与隔离合同验收通过，未提交真实 GPU 研究任务。

## 使用顺序

1. 打开“设置 → 服务器与脚本”，在左侧选择服务器。
2. “连接”展示当前 SSH 别名。读取本机配置与测试免交互连接是独立按钮；保存默认值不会执行连接测试。
3. “任务脚本”只列当前服务器、调度器与程序的记录。上传、粘贴和编辑副本使用同一对话框；原稿保持，副本关联原记录。导入后立即刷新，选中候选后在下一步保存默认值。
4. “提交默认值”只有一个保存入口，按服务器与程序保存。默认使用导入正文；已有 MPI、环境与程序路径放在高级登记方式中。全局额度与缓存移到“运行与监控”。
5. 从提交区打开设置时携带服务器、程序和脚本入口。“返回提交任务”保留原提交草稿、节点信息和候选池。编辑名称、walltime、CPU/MPI/GPU 数量或脚本会清除旧确认，保留同一连接目标的节点事实；最终派发仍实时复核。

添加服务器才展开首次配置表单。脚本加载中、读取失败、没有对应脚本与已有登记方式分别显示；读取失败不伪装成空列表。快速切换上下文丢弃过期响应，操作期间锁定服务器与程序。

## GPU 合同

沿用既有 API。`config.resource_request` 可以是对象或序列化 JSON；计算链也可在每步 `resources[node_id].resource_request` 中冻结请求。示例：

```json
{"mode":"gpu","mpi_ranks":1,"gpus":1,"allocation":"whole_node"}
```

按程序的草稿使用 `{"by_program":{"vasp_std":{...}}}`。没有请求的旧调用继续使用 CPU 合同；`gpu_vasp` 是 VASP 常规的 GPU 模式，不另建调度框架。

MPI 进程数与整节点预留分开：GPU 任务预留所有 CPU 和 GPU，启动 MPI 数量保留原稿意图。GPU 数量来自明确资源头或固定设备列表，缺项要求填写，不根据文件名推断。PBS 以总 CPU 数配置 `ppn`，存在 GPU 登记时追加总 GPU 请求；Slurm 使用单节点、原 MPI 数、`--exclusive` 与全节点 GPU GRES。GPU 类型和固定设备编号必须对应实际节点。

环境加载、程序路径与固定 `CUDA_VISIBLE_DEVICES` 保留。仅明确识别的 PBS_NODEFILE/SLURM_NTASKS 派生 `NPROCS` 在执行副本中适配，并展示差异；固定参数冲突、未知进程表达式和多节点布局阻止执行，要求编辑副本。原稿不改。VASP OpenACC 模式按有效 `NCORE=1` 检查 KPAR，不改原 INCAR。

Torque 未登记 GPU 时，只对 SSH 实际连接到该计算节点、节点身份匹配的单节点回执读取物理 GPU 和活动计算进程。身份、卡数、设备编号或分配信息未知时明确阻止。CPU/GPU 占用、活动 GPU 进程和负载未恢复进入容量等待；参数迭代和链的子项保留 PENDING，容量恢复后再派发。活动计数和实时空闲数不进入冻结配置比较；脚本、请求和实际 SSH 目标变化要求重新确认。

walltime 统一验证正值 `HH:MM:SS`，小时不限两位，再检查实际队列上限。历史输入、冻结资源、授权和 attempt 不迁移。一次性本机默认整理记录精确的旧、新默认快照，兼容原 legacy 授权；普通设置修改仍执行原失效规则，显式冻结脚本与实际 SSH 目标仍独立核查。

资源接口依据：[Torque GPU 请求](https://docs.adaptivecomputing.com/torque/archive/3-0-2/3.7schedulinggpus.php)、[Slurm sbatch](https://slurm.schedmd.com/sbatch.html)、[VASP OpenACC GPU port](https://www.vasp.at/wiki/OpenACC_GPU_port)。未承诺防止节点管理员在最终检查之后启动其他手工进程。

## 验收证据

- Safari 原生验证设置阅读顺序、服务器选择、添加对话框、粘贴导入、编辑关联副本、即时列表更新、保存默认以及提交页往返保留服务器、脚本和名称；正式服务确认六台服务器和 GPU 默认记录显示。隔离浏览器补充上传、程序与服务器快速切换，以及往返保留 1000 小时 walltime、GPU 请求和节点事实。原生文件选择器自动操作未完成，Safari 上传仍需人工复核；已移除扩展名过滤，正文调度器核对保留。
- 读取失败与保存失败注入分别显示具体错误，登记方式保留，保存失败没有继续诊断。修改元数据、脚本及设置往返新增远端探测为 0；隔离 UI 全程真实 SSH=0、调度提交=0，worker 关闭。
- 后端隔离覆盖 GPU 单任务冻结、迭代和链的 busy→PENDING→idle 派发；重点覆盖调度 free 但有活动 GPU 进程、未知身份、资源/设备冲突、固定与派生 MPI 数、脚本修改、CPU 旧合同及 legacy 默认兼容。空闲派发均是模拟回执，不是实际程序结束证据。
- 空工作区 Python 全量 422 项通过（2 跳过）；最后的进程表达式收紧后，相关派发/模板/默认合同 99 项通过。前端 83 项、类型检查与生产构建通过。测试必须指定独立 `FPILOT_WORKSPACE`，避免个人默认记录进入测试夹具。
- 正式服务重启且健康，原 worker 开关保持。没有 ACTIVE 迭代/链，没有新增运行记录；全部迭代与链记录保持原样。原 UNKNOWN attempt 仅被既有监控刷新状态回执耗时与更新时间，其状态、冻结输入和授权未改变。
