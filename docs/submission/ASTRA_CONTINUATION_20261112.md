**Astra 架构建议分两轮推进 · 第一轮交付 · 2026-11-12**

按最新架构评估的顺序，本轮完成批量后续计算和结果操作入口。第二轮接统一文件传输、结果管理和历史查询。SQLite、冻结输入、准确 attempt、来源合同、现有派发器及独立扩展继续作为实现基础。

已完成的用户流程从优化批次或某个 case 的历史结果开始。点击“基于所选结果创建 SCF 批次”，勾选全部或部分可用项，填写统一 INCAR/k 网格覆盖并预览，随后创建新的冻结批次和一个画布节点，进入运行审阅。每个新 case 的 POSCAR 来自所选运行的 CONTCAR，物理设置和 k 网格来自对应运行，统一覆盖在输入差异中展示。原扫描条件以“来源”前缀显示，实际 SCF 设置保存在各自冻结输入中。

默认仅接力结构，CHGCAR/WAVECAR 可按需要选择，兼容性判断沿用 source_contracts。来源候选依据原运行的程序结束、最终电子和离子收敛证据列出资格。文件缺失或输入有问题时预览逐项说明，用户可以保留检查通过的子集再预览。当前批次授权使用单个服务器配置，按来源主机分别创建后续批次。

创建会固定每项的来源 batch、case、attempt、作业号、所需文件和文件身份。原批次重试、改名或调整显示顺序后，已有来源保持指定运行。历史结果页按显示的 attempt 预选。预览后来源变化要求重新预览，派发前继续由现有来源合同复核。后续节点配置页展示已冻结 case，运行页显示来源作业与结构体积。

创建操作以预览 ID 幂等，并发重试返回同一批次。冻结中断时保留已有内容寻址输入，批次表在全部 case 准备成功后一次保存。创建期间使用已有 attempt 操作锁，待执行批次的准确文件依赖进入现有清理引用检查。工作区草稿更新按当前项目合入新增节点，创建请求返回后发生的项目变更也由最新草稿保留。刷新或丢失返回后，可在原批次入口打开“已创建的后续批次”恢复节点和运行审阅。复制后续节点会清除原批次身份。

新增 API 在独立 router 中，主体沿用既有批次和执行合同。

| 接口 | 作用 |
|---|---|
| `GET /api/scans/{batch_id}/continuation-sources` | 读取可选 case 与已经创建的后续批次，支持指定历史 attempt |
| `POST /api/scan-continuations/preview` | 核对所选来源与各自 SCF 输入 |
| `POST /api/scan-continuations/{preview_id}/create` | 按预览冻结各 case，幂等保存新批次 |

清单 JSON/CSV 新增 `continued_from`，保存来源坐标、准确运行和所需文件。当前新 attempt 使用用户项目下已有的 `flows/main/stages/.../attempts/...` 布局。批次实体目录外层随后续文件准备与清理合同一起处理。

验收使用临时工作区和三个不同晶胞的合成优化结果。新专项覆盖三结构一一对应、参数/k 网格继承和统一覆盖、子集顺序、历史来源、原批次重试与重命名、缺失/未收敛来源、可选 CHGCAR、来源文件变化、冻结中断、并发创建，以及待执行消费的清理引用。后端全量 945 项中 940 通过、5 跳过，前端 178 项通过，类型检查和生产构建通过。独立 Chrome 的 11 项检查走通历史结果到运行审阅、刷新恢复和单次创建请求，运行时异常为 0，授权及提交请求为 0。真实服务器的计算闭环待专用目录验收。

运行中的后端需正常重启加载新接口。短回执、浏览器截图与一次性验收脚本在 `workspace-data/development-records/astra-continuation-20261112/`。

第二轮优先交付可恢复文件准备与收集，让传输任务拥有独立持久化状态，按来源版本复用文件，临时文件成功后发布。小文件与控制消息沿用已有能力，统一适配层接管文件传输并消除按特定主机名选脚本。计算、收集和展示状态分别恢复，失败操作定位原结果并补做相应步骤。扩展输入准备接入同一套宿主机制。

随后收拢结果目录与历史列表。完成结果直接进入目录，独立快照作为可选保存动作，历史格式按适配器读取。分析明细继续保存文件，列表使用轻量 SQLite 索引。删除操作按对象复用已有生命周期实现，普通入口保持一致。API 和公共请求机制随这些业务动作逐项整理。
