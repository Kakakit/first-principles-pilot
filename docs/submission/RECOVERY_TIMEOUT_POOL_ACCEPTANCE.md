# 恢复提交延迟与候选节点池修复 · 2026-10-17

## 结果

恢复确认接口先原子保存本次授权范围，立即返回，再通过 FastAPI 已有后台任务处理准备和提交。现有 worker 与后台任务使用相同操作锁、确定性 attempt ID 和提交记录；重复确认、并发 worker 或重新读取回执不会新发一次作业。界面按阶段显示核查资源、准备输入和等待调度回执，可关闭后重新读取同一操作。

UNKNOWN 明确显示“提交回执不明”，同时保留原始错误、目录阶段与作业号情况；不再用“原回执状态已保留／处理完毕”替代结果说明。输入准备失败可在原面板返回修改，读历史操作时读取当前实际 attempt 回执。已结束的处理范围和计算是否完成分别显示。

远端命令超时后，最多再用 2 秒收集剩余输出。即使子进程卡在内核文件系统 I/O、无法及时关闭管道，也返回已取得的阶段日志，不再无限等待。没有确认的提交仍为 UNKNOWN，不自动重发。

候选节点选择会把本机已有 SUBMITTED、QUEUED、RUNNING、DISPATCHING 等在途回执作为占用证据。即使同轮服务器快照尚未反映第一项提交，第二项也优先使用另一个候选；只有一个候选时留在本机等待。直接交调度器的策略仍允许排队，并优先分散到尚未被本机请求占用的候选。已准备且固定了节点的 attempt 不被静默改写。

- 原确认请求耗时 185.67 秒；准备不足 1 秒，提交等待超时，最终 UNKNOWN 且无作业号。

- 使用真实 Ce 项目的结构、POTCAR、网格和脚本建立独立验收分支。原项目、原 attempt、原冻结包与研究目录保留；独立运行设 10 分钟上限。真实作业 `25398.node01` 已取得回执，并核查到 PBS `R`。这是提交流程验收，不是收敛或物理有效性验收。

## 使用与边界

点击“确认提交此项一次”后看到“授权已保存”只表示本次范围已持久化；调度器确认以逐项作业号为准。出现 UNKNOWN 时先读取、核查原作业；若明确另投，使用新的预览与确认。旧操作不会因超时自动再发。

两个候选节点是可供独立作业使用的池，不会把单个作业自动拆成跨两节点计算。有依赖的链步骤仍等待上游。候选池避免本机刚提交任务造成的选择滞后，无法替代调度器处理其他用户的竞争、队列优先级或资源保留。
