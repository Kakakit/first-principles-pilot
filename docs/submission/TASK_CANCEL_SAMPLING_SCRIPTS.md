# 取消任务、POSCAR 点数取样与脚本删除

## 使用

- 运行审阅、结果页执行证据、计算链步骤和迭代 case 表提供“取消任务”。先核查目标再确认；默认聚焦“保留任务”。待派发 case 只取消本机登记；已提交任务按准确作业号调用 PBS `qdel` 或 Slurm `scancel`。
- 确认取消时，所属批次或链暂停后续派发。其他已运行任务保持；输入、授权、文件和历史保留。恢复批次后跳过已取消 case；取消的链步骤阻止下游与条件续算，需另行准备并授权。
- “已接受取消请求”与“已确认停止”分别显示。未知回执只读核查，同一令牌仅执行一次；传输层明确标记取消为写操作，不缓存或重试。明确未发送时可重新预览。缺准确作业号、身份不符或调度器不可用时不能猜测目标；队列里没有作业不证明已停止。
- POSCAR“取样方式”可选自定步长或指定点数。点数为 2–64，包含两端；间隔为 `(终点−起点)/(点数−1)`。每点独立计算，循环小数步长不会漏掉末点。整批最多 64 个 case；目标体积填写正数、POSCAR 写负 scale 的语义保持。
- 软件设置 → 服务器 → 任务脚本，使用“删除脚本”。脚本移入统一回收站，可恢复；历史冻结输入与执行脚本保留。引用脚本的未派发计划暂停。删除默认脚本后重新选择并保存默认值，不自动换用另一份脚本。

## 合同

取消接口为 `POST /api/execution/{id}/cancel-preview`、`cancel`、`cancel-status`。均接收 `project_id`；确认额外接收预览 `token` 与 `confirm=true`。10 分钟预览绑定 attempt、主机、路径、准确作业号及关联计划。待派发 case 使用 `POST /api/scans/{batch}/cases/{case}/cancel`。共享容器派发锁、设备归属门禁和 attempt 操作锁，确认前重新核查。

`CANCELLED` 为不可变终态。受理取消但尚未停止仍占在途额度；UNKNOWN 不重投。Slurm 使用准确 accounting 行；PBS 受理取消后仍需终态与非零退出证据。自然完成和未经证实的失败保留原判定。回执保存在 attempt 的 `cancellation` 及事件日志，随项目接续保留。

调度器入口依据 [Slurm scancel 官方文档](https://slurm.schedmd.com/scancel.html) 和 [TORQUE qdel 官方文档](https://docs.adaptivecomputing.com/torque/6-1-0/adminGuide/Content/topics/torque/commands/qdel.htm)，使用已有命令行薄适配，不增加调度器依赖或强制终止进程选项。

POSCAR 维度可选 `sampling="count"`、整数 `point_count`；缺省仍为旧 `step` 模式。旧项目、批次、冻结文件不迁移。

## 验收与限制

真实 Ce 相变研究的导入结构及参数在私有隔离副本中预览四个体积：95.049、102.089666…、109.130333…、116.171 Å³；两端、点数越界、原步长保留通过。副本显式连接本机结构为基准，不声称核验现有远端来源。浏览器核对真实 PREPARED 记录的取消预览与默认保留，以及实际脚本列表的删除确认；未确认取消或删除研究记录。

真实服务器只读核验受阻：Ce 服务器 `10.201.0.187:22` 连接超时，PBS 连接也未建立有效 SSH 会话。未发送研究任务的 `qdel/scancel`。远端实际取消仍待联网后按用户指定任务验证。框架回归覆盖准确 PBS/Slurm 命令、身份与所有者、未知回执恢复、单次令牌、状态变化、关联计划暂停及取消后不重投。

正式服务原任务、冻结输入、授权合同保持，worker 仍为 300 秒。私人项目、脚本、截图、回执及 SQLite 备份不发布。

最终筛选发布副本：后端全量 635 项（3 跳过）、前端 124 项通过，类型检查与构建通过。正式服务重启核验保留原 84 个任务、10 条链、3 个批次及 119 个冻结文件合同；未恢复原暂停/受阻计划。私人回执在本机归档。
