# PyW90 冻结窗：超额态与边界极值

在“检查当前草稿窗口与下界”、eig 或 pre dos 的完整接口检查中，新增“冻结窗边界与超额态”。直接读取接口 `.eig` 的全部已提供 k 点，使用该通道实际 `num_wann`；不改 PyW90 原生候选算法或排序，不自动选择拟合模型。

## 使用与解释

- 两张卡片分别固定下界、固定上界。展示严格临界值、对应 `.eig` 带号和 k 点、该带的全网格最小／最大能量及其位置。附近能带表列出穿过上下界的带，以及各边界上下方最近带；超额时默认展开。
- 页面能量统一为 E−E_F / eV，临界值与极值保留八位小数；后端保留绝对能量。带号和 k 点号从 1 开始，属于接口文件，不能将 exclude_bands 后的编号直接当作原 DFT 带号。
- “窗口内第 N+1 个态”从当前固定边界计数，不是整份 `.eig` 的第 N+1 条带。固定边界穿带时，对应带号可能随 k 点改变，该带全局极值与逐 k 点临界值也可能不同，两者分别展示。
- 临界值外侧 1e−6 eV 仅作数值试算，展示全网格最少／最多态数。“预览”重新核验真实来源和四个窗口，完整约束通过后才能确认填入一个参数字段；其他字段保持，还须显式应用到 `.win`。取消保留草稿。修改草稿或设置后旧临界值按钮失效，重新检查后恢复。
- 简并可能一次去掉多个态。界面显示能否仅调该侧让所有采样 k 点恰好有 N 个态；该条件不是冻结窗的要求。冻结窗只需最多不超过 N，是否覆盖想要的轨道和拟合能区仍须人工核对。

## 计算规则

记 N=num_wann、当前冻结窗下／上界为 L、U：

1. 固定 L：每个 k 点把本征值按能量排序，取 ≥L 的第 N+1 个值 q(k)。上界必须满足 U<min q(k)。没有 N+1 个可计入态的 k 点不限制上界。
2. 固定 U：按能量降序，取 ≤U 的第 N+1 个值 p(k)。下界必须满足 L>max p(k)。
3. 端点也计入，不能直接采用等于临界值的边界。即使当前有 N+3 个态，也仍使用 N+1 的临界值，并对新窗口逐 k 点复算。
4. 每个 k 点恰好 N 的区间，由第 N 个值和第 N+1 个值的交集给出；交集为空或某些点不足 N 时显示不能通过单边界实现。数值试算明确显示真实计数，不承诺正好 N。

只针对已提供的接口 k 网格；不声称连续布里渊区满足同一限制，也不将态数约束通过当成程序收敛或最佳拟合。

## 验收

真实学校服务器核对当前下自旋草稿，复现完整 216 k 点、96 条带、num_wann=54 的 54～55 个冻结态。固定下界时，上界临界值外侧试算为 52～54 态；固定上界时，下界临界值外侧试算为 53～54 态。后者的逐 k 点临界值不同于对应带的全局最大值，验证了不能机械套用单条带全局极值。精确能量、位置和私人输入留本机回执。

从同一真实 `.eig` 的实际本征值构造 57 态窗口并重新在服务器检查，固定下界所得第 55 个态的临界值保持。另一真实自旋通道及 SOC 单通道接口也核对；SOC 使用实际 num_wann=108 和第 109 个计入态，没有人为拆成上下自旋。分析前后原 OUTCAR、`.win`、`.eig` 文件身份保持。

浏览器通过正式 API 检查、单上界／下界预览、取消、采用到隔离页面副本、旧诊断失效及重新检查；验证极值表、五套主题和窄屏。项目草稿、输入、冻结包、任务与链／扫描授权保持；未准备或提交研究计算。一次性脚本、真实输入与私人回执只留本机开发备份。

相关后端 67 项通过；最终发布副本全量后端 586 项（3 跳过）、前端 104 项、类型检查与生产构建通过。

## 源码依据

- [PyW90 suggest_froz_min／suggest_froz_max](https://github.com/Cloudiiink/pyw90/blob/master/pyw90/lib/w90.py) 原生实现使用能带全局范围，本包额外补充逐 k 点精确计数和位置。
- [Wannier90 3.1 冻结窗端点与 ndimfroz 检查](https://github.com/wannier-developers/wannier90/blob/v3.1.0/src/disentangle.F90)：端点包含，冻结态超过 num_wann 时拒绝。
- [Wannier90 参数缺省值](https://wannier90.readthedocs.io/en/latest/user_guide/wannier90/parameters/)：没有 dis_froz_max 不启用冻结窗；dis_froz_min 默认沿用外窗下界。
