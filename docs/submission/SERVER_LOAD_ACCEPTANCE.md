# 服务器访问减负与有限恢复 · 2026-10-19

保留现有本机绘图缓存，优化故障恢复、后台查询、文件枚举和首次分析。此次只运行本机隔离验收，没有连接故障集群，没有提交、取消或重投研究计算，没有发布安装包。

## 使用变化

- 首次连接失败后，间隔 15 分钟最多额外自动恢复 5 次，耗尽后暂停。手动恢复一次只运行一个固定 `printf` 探针；成功清零，失败保持暂停。并发恢复共享同一回执，旧记录中保存的故障业务命令不会执行。
- 调度器拒绝和程序报错保留为业务错误，不消耗 SSH 恢复预算。连接恢复不重放提交、文件核查或失败分析。
- UNKNOWN 没有 job ID 时，后台只读取原 `.job-id`。文件核查超时后，该项停止自动深读，仍可手动核对；已知 job ID 的调度跟踪继续。终态核查复用未变化文件的证据，同时继续查询调度终态。
- 后处理环境在本机后台首次检测，按扩展版本、Python 路径及解释器版本标识缓存。同一服务进程中切换、重开、实际运行复用检测回执；“检查所选环境”明确重检。启动时不检查所有远端主机。
- 文件列表先显示本机记录，只为可见页面低频更新元数据；60 秒内复用记录，隐藏页面停止刷新。过期、未读取或截断清单不作为文件缺失证据；实际准备、提交和来源复制仍执行必要核验。
- 已有绘图直接显示；首次生成合并 OUTCAR 费米能、带边、SOC 与哈希提取。VASPKIT 常规计算失败不自动完整再跑一次。大型只读数据在独立生成目录使用链接，来源前后元数据仍核对。
- 同一主机重分析串行，普通跟踪保持独立；已有授权的扩展等待前项完成。本地和远端直接分析默认使用一个 BLAS/OpenMP 线程，明确配置的分析核数优先；VASP/MPI 申请和脚本不变。本地扩展超时同样限时收尾，未确认退出保留 UNKNOWN。
- 仅远端投影请求使用 500 毫秒防抖；一个请求执行期间只保留最新待处理选择。已有本机图表使用原有响应速度，不降采样。
- CPU 请求不附带 GPU 诊断。删除预览不再递归统计容量，显示“未统计”；目录身份、调度状态、拒绝覆盖和删除确认保持。

## 调用次数与实现

| 场景 | 原实现 | 本轮实现 |
|---|---|---|
| 20 个同主机任务核查 | 1 次 SSH、20 条 qstat 命令 | 1 次 SSH、1 条多 job ID 命令 |
| 扫描 OUTCAR 摘要 | 2 次哈希、4 次 grep、1 次 awk | 一次流式读取，同时提取指标和哈希 |
| 重读未变化的扫描来源 | 重复全文读取 | 当前元数据核对后复用同一来源版本 |
| 文件清单 | find 递归，每文件多个外部命令 | 单 Python 进程，最多 2000 项访问、10 秒软预算 |
| 连接恢复 | 重放故障读取，可能扫描 OUTCAR | 固定小探针，不启动科学 Python |
| 扩展超时收尾 | 杀进程后可能无限 wait、遍历 /proc | 记录所属进程组，终止后最多等待 2 秒 |

这里统计的是应用命令和文件读取次数，不将其等同于磁盘物理 I/O 或调度器内部 RPC 次数。无法确认终止的进程保留 UNKNOWN；软件不能保证结束内核 D 态进程。

复用现有 transport、worker、文件锁、缓存和执行器，没有增加工作流框架或依赖。派发轮次共享容量快照和本机预留，真正提交前的实时检查保持独立。轻量模式对大于 1 MiB 的普通输出使用元数据证据，原有检查点策略保持；必要输入、完整核验模式和提交前冻结内容检查保留。

GET `/api/execution/{key}/artifacts` 只读本机观察；POST `/api/execution/{key}/artifacts/refresh` 合并实际刷新。返回 `needs_refresh`、`refreshing`、`host_state`；扩展上下文不再隐式扫描远端。旧记录按缺省字段读取，不迁移目录、attempt 或授权，不自动启动历史暂停计划。

## 验收

活动源码后端全量 794 项、GitHub 交付副本 780 项通过（各 3 跳过）；对应前端 145／142 项、类型检查与生产构建通过。覆盖持久重试预算、并发手动恢复、业务错误区分、不可退出子进程、部分调度回执、来源版本失效、枚举预算及 UNKNOWN 手动接续。回归复用本机已有登记和脚本样本作为只读测试输入，这些私有文件不进入源码提交。

真实项目副本的浏览器验收中，6 次扩展切换约 54–203 毫秒；重开面板后环境检测次数不增加。已有 fatband/PDOS 的缓存接口约 13–15 毫秒，没有调用重新生成接口。面板移出视区后，后续验收期间上下文请求计数保持不变。

模拟 2 秒远端投影回执，连续修改上界 5、6、7，实际仅提交最终 7；同时最多执行一个请求。该延迟为本机模拟，曲线来自项目副本缓存，不是真实远端性能测试。整个隔离浏览器过程真实 SSH 进程数为 0。

源码同步以 GitHub 当前 main 为父提交，仅合并本轮差异；其他开发改动、研究数据、POTCAR、服务器配置和验收副本不进入提交。私人脚本、截图、原始回执和调用计数归档在本机开发备份中。正式工作台的服务和 worker 状态保持，正常重启后加载源码更新。

这些修改消除已确认的软件负载放大问题；现有证据不能证明软件引发了最初的磁盘 I/O 故障。固定探针仍经过 SSH 登录流程，不绕过服务器家目录或登录初始化。
