# 阻塞提示与设置定位 · 2026-11-16

按 Astra 最后一轮“点击下一步时解释阻塞并定位修改”的方案实施首批三个入口：普通 VASP 节点的输入审查/冻结、准备提交，以及通用独立扩展运行。沿用当前导航和验证规则；本轮不扩展计算链、扫描或 Wannier 专用表单的逐项定位。

## 使用行为

遇到已有阻塞条件时，按钮保持可点击，并在本次点击后列出需处理的问题。点击“去修改”或“查看上游任务”，打开原问题所属项目、节点和分区，展开相关内容，滚动、高亮并聚焦字段。修改后可通过“返回并重新检查”回到发起位置，对当前数据重新检查。输入审查返回后生成新的预览；准备提交只重查本地前提，扩展只重新验证当前来源/环境元数据和表单。它们不会自动冻结、准备 attempt 或提交计算。

- 输入错误对应网格/路径、POTCAR、来源、INCAR、磁矩和 LMAXMIX。冻结所需的理由和人工核对也在点击时说明，规则不增加。
- 准备提交缺少冻结输入、服务器或计算节点时分别提供定位入口，旧来源合同仍需回到来源页重建。
- 扩展的 JSON Schema 错误携带实际字段路径；环境问题展开并聚焦对应扩展的实际环境分区，未登记服务器环境时定位到登记主机字段，上游结束证据不足指向准确的历史 attempt 和可见节点。虚拟 case 的导航使用所属画布卡片，attempt 身份保留。
- 警告继续显示为建议，不加入阻塞弹窗。输入过程中不弹窗。
- 普通旧错误保留原文与重试指引，不用中文错误文本猜测字段。未知错误返回时提示手动重试，不宣称已经解决。
- 项目参数草稿和现有运行草稿继续沿用原保存机制。扩展选择、参数、额外来源、运行位置和别名使用有界会话缓存，支持往返设置页。预览授权、运行确认和执行回执不放入该缓存。会话缓存不代替工作区持久保存，超出缓存限额的附件不新增永久副本。

## 实现与兼容

`backend/action_issues.py` 将稳定的问题编号和页面/字段目标附加到现有阻塞说明。输入预览新增 `issues`，原 `errors`/`warnings` 与生成文件保留。冻结和扩展字段错误可通过 HTTP `detail.message`/`detail.issues` 返回；普通字符串错误继续支持，原 ValueError 消息兼容。

前端共用 `ActionIssuesHost`，以当前操作注册重新检查入口；返回后使用新挂载组件的最新数据。导航 URL 保存字段焦点，懒加载完成后再定位。输入、运行及扩展各自保留准备和执行逻辑。读取设置复用原组件的在途请求，不增加额外远端探测，也不创建通用执行引擎。

本轮没有改变 INCAR 物理默认值、科学算法、来源文件复制、远端调度或清理规则。
