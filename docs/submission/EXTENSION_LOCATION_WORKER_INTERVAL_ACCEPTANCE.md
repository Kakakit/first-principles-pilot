# 扩展运行位置与 worker 周期 · 2026-10-20

后处理的运行位置以用户当前选择为准。切换到同时支持本地和服务器的扩展时，不再使用包的推荐位置覆盖选择；不支持当前选择时才使用可用位置。临时切换不会改写手动偏好，返回兼容扩展时恢复该偏好。来源／环境的异步更新同样遵循此规则。这里只调整通用宿主页面，不修改扩展包或历史分析。

设置页“持久监控与在途额度”新增“worker 核查周期（秒）”，填写正整数并点击“保存监控设置”。默认仍是 300 秒，原设置文件缺少新字段时也使用 300；旧客户端只保存额度时保留已设置的周期。新值保存在工作区 `execution-settings.json` 的 `worker_interval_seconds`，重启后沿用。输入无效时不会覆盖已有设置。

默认 worker 在当前核查完成后，或已有等待过程中，读取新周期；从上一轮完成时刻重新计算等待期限，缩短／延长均生效，不增加并行核查。等待期间每秒只读取本机小设置文件，不增加 SSH 检测。原主机冷却期限、五次重试预算、单 worker 锁、停止文件和退出行为保持。显式 CLI `--interval` 仍覆盖保存值，页面显示当前周期并说明该来源；启动器默认不传此参数，因此开发版和安装版均采用保存值。

专项覆盖旧文件兼容、旧客户端保存、无效值不写入、周期缩短／延长、CLI 优先级、主机恢复期限及隔离 worker 的单实例／重启。相关后端 34 项、前端 15 项、类型检查和生产构建通过。另有一项无关的 Wannier 恢复测试因交付副本缺少该服务器随附脚本失败；精确父版本单独重跑具有相同失败，未改动其脚本逻辑，不声称所有跨域测试通过。隔离浏览器验证扩展切换、手动偏好恢复与周期保存；样例 worker 只记录本机轮次，不执行任务或连接服务器。

交付仅同步本轮增量，不混入其他开发改动，不重启正式服务或更改实际监控周期，不发布安装包。现有进程需正常重启以加载新代码；此后周期设置可在线修改。
