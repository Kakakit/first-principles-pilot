# 候选节点负载等待修复 · 2026-10-05

PBS 和 Slurm 的只读预检会将调度器空闲、但未登记 CPU 负载超过阈值的节点标记为 `SUSPECT_LOAD`，并把可用核数设为 0。之前候选池只对 BUSY/FULLY_IDLE/PARTIAL 的纯容量不足等待；SUSPECT_LOAD 导致批次 BLOCKED，即使冻结资源和脚本完全一致，界面也误报“资源或脚本已偏离授权预览”。

现在纯容量/负载不足保留批次 ACTIVE、case PENDING，显示“调度器空闲但负载未恢复，等待复检”。worker 每轮检查实时容量，恢复后沿用原核数和脚本授权。没有把 SUSPECT_LOAD 当作可提交容量，也没有取消最后一次派发前检查。候选池支持提前选择这种节点并等待。

离线、异常 MOM 心跳、队列/运行时诊断失败仍阻塞，并显示具体资源检查原因；真正脚本或 profile 变化仍要求核对授权，UNKNOWN 仍不重投。若批次已经被旧版本误置 BLOCKED，更新后刷新页面，选择该原批次并点击“继续批次”。更新不会自动恢复显式暂停或旧阻塞批次，不需重新冻结或重跑已完成 case。若原授权确实发生变化，继续后仍会提示核查。

- 105 项相关 Python 用例通过，覆盖真实预检解析与脚本渲染下的 PBS/Slurm：BUSY、SUSPECT_LOAD、部分核数不足等待，空闲恢复保持准确授权；UNAVAILABLE、SUSPECT_MOM、诊断失败、脚本变化仍阻塞。
- 3 项前端相关用例、TypeScript 检查、生产构建通过。
- 实际冻结批次的本机隔离副本精确复现旧报错；修复后等待期间 prepare/submit 均为 0，空闲恢复只产生一个模拟后续提交，已完成 case 不变，显式暂停有效。回放不调用远端、不更新正式批次、不执行真实作业。

此次更新为源码补丁，现有运行 ZIP 不自动更新；其他设备需更新源码并重新构建/打包。真实节点的后续状态和科学结果须由实际运行证据确认。
