# 独立参数迭代与逐 case 接续

参数迭代节点在自身保存基础计算设置，通过 `scanSpec.calculationKind` 选择 relax、SCF、能带、DOS、VASP-Wannier 或 Wannier90。画布和阶段身份仍是 scan；输入、科学审核和依赖规则使用实际计算类型。普通新项目继续使用 08-scan，已有项目目录不变。

## 使用

1. 新建参数迭代，在计算配置选择计算类型；画布连线或“连接实际上游”均遵循普通计算的依赖规则。可预览复制已有节点的设置。
2. 配置物理参数、来源、k 点与赝势（Wannier90 使用实际接口与通道草稿），然后在下方定义扫描范围。无需先冻结一个基础任务。
3. 预览全部 case、准备批次，再进入运行审阅确认资源和脚本。每个 case 仍走普通冻结、prepare/submit 和 worker；独立目录、输入和授权保持。
4. 在结果与后处理选择这个迭代节点，然后按批次、case、运行版本查看记录、文件、证据、取消任务或后处理。POSCAR 扫描分别显示目标体积与读取后的实际体积。
5. 下游连到迭代节点，在计算来源中明确选择 case 和 attempt。合格结果不必等待整批结束，无需批次提升；不同下游可以选择不同 case。普通计算链仅复用这些明确选择的来源，不自动运行迭代批次。

参数优先级为节点显式覆盖、下游阶段默认／预设、所选 case 实际 INCAR、项目共享设置；来源合同继续控制 ISTART/ICHARG。U/J 按物种顺序、MAGMOM 按原子顺序映射；静态节点不继承优化控制。冻结记录参数来源和实际输入身份，INCAR/.win 不加入文件复制计划。来源改变后须重新预览，旧冻结不被改写。

## 兼容与边界

旧节点继续跟踪原批次，可点击“改为独立迭代 · 预览”，查看计算类型、参数及实际上游后应用；工作台撤销可恢复草稿。升级不更改基础节点、历史 node_id、目录、冻结包和授权。旧 case 按执行归属与批次归类。已有冻结、批次、来源引用或回收历史时不能改变计算类型，复制后可重新配置。

程序结束、电子／离子收敛、文件存在和物理验证仍分别判断。失效、缺文件或 UNKNOWN 来源阻止接续；不自动换来源、重投、恢复暂停／受阻批次，或恢复已永久清理的冻结包。技术身份保留在详情。

## 验收

专项覆盖六种类型的普通输入合同、scan 阶段准备、独立冻结归属、旧 case 归类、缺省静态设置、实际 U/J 与有序磁矩、enum 大小写、显式覆盖、两条下游选择不同 case、计算链不派发批次，以及能带路径绑定保持。Wannier90 草稿基线无需单独冻结，冻结 case 的 node_id 与 execution_scope 指向 scan。前端覆盖普通连线、旧模板兼容、显式升级与不改写基础节点。

业务验收使用真实项目的隔离草稿与真实服务器只读核验。真实 U 扫描及 EOS 的文件、结构、参数值、旧记录归属和已清理输入的拒绝分别核对；没有提交、取消或重投研究任务。浏览器验证批次／case／版本、文件日志、升级预览／应用／撤销、新类型与上游入口，以及 EOS 下游参数继承。正式数据、远端目录和授权保持。

发布前执行全量后端、前端回归、类型检查和构建；日志、研究证据及截图留私人备份，不上传赝势、研究记录或服务器配置。

最终公开副本：后端 646 项（3 跳过）、前端 126 项，类型与构建通过。正式服务重载前后原任务、链、批次、授权与冻结文件合同一致。真实 case 另生成了仅保存在私人目录的下游冻结 ZIP，验证实际结构、U/J 和静态控制；未准备或派发研究计算。
