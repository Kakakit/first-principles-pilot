# 工作台白屏修复与本机控制

## 修复原因

真实 Ce 项目切换到结构板块时复现 RJSF `Invalid hook call` / `useCallback` 为空。正式 Vite 使用的预优化缓存已被共享 node_modules 的验收副本覆盖，路径和依赖版本标记混用，产生两份 React。改为每个目录独立 `.fpilot-cache/vite`，限定入口扫描并统一 React 解析；研究数据目录和控制运行目录不参与监听。

板块级错误边界保留导航，支持返回概览和查看原因；全局边界提供重新载入。工作区尚未连接时显示明确提示及重连入口，避免把暂时不可读的占位草稿当成原项目丢失。

## 使用

Mac 源码目录双击 `First Principles 工作台.app` 即可打开控制页，正常启动无需终端。应用须与本目录保留，可建立 Finder 替身。备用 `打开工作台.command` 自动定位已有 Node；使用原 `fpilot.local.json` / 登记 Python。没有安装依赖或创建环境。

默认控制页 `http://127.0.0.1:5174`，网页 5173，API 8000。控制页可打开网页、启动、停止、重启、读日志和退出控制中心；关闭网页保留后台服务。停止／重启前保存项目；确认框默认取消。停止后本机监控／自动推进暂停，远端作业保留，重新启动沿原授权推进；UNKNOWN、暂停及受阻不重投。

启动、停止和重启串行；先等待 API 就绪，再启动 Vite，避免旧浏览器自动重连时的代理失败。正在派发时核对完整只读 SQLite 记录，包含超过历史列表 100 条上限的旧记录，阻止中断回执。进程由当前控制中心的子进程对象管理，退出等待结束，不强杀陌生端口程序、不执行远端取消。控制请求限定回环 Host、同源及本机随机令牌；身份／日志仅留忽略的 `.fpilot-runtime`。旧或不可核验的实例不能仅凭端口占用自动认领。

CLI 兼容 `npm start`、`npm stop`、`npm run restart`、`npm run status`。控制端口可用 `control_port` 配置；修改控制端口前退出原控制中心。这里改进源码开发入口，现有无 Node 的运行 ZIP 保留原启动方式，本包不重新发行 ZIP。

## 验收边界

真实本机服务及 Ce 项目核验白屏消失、表单／画布／配置／监控／结果可显示；控制页停止、再启动、重启、重复入口复用、默认取消、日志与未授权请求拒绝。专项覆盖操作并发、重复启动、完整派发记录及有界日志读取，现有便携启动与进程退出回归通过。最终公开副本后端 607 项（3 跳过）、前端 120 项、类型检查与构建通过。测试用例在隔离数据内运行，业务验收使用真实项目记录和正式服务。

原 86 个任务、13 条链、2 个批次、171 个冻结文件合同核对保持；原本机配置及 worker 300 秒保持。没有创建分析、修改远端输入、提交或取消研究计算。在线 SQLite 备份、操作记录及截图保存在本机开发备份，私人文件不发布。

实现采用 Node 内置进程与 HTTP 能力及现有 Vite，不增加桌面框架依赖；依据 [Vite 去重](https://vite.dev/config/shared-options#resolve-dedupe)、[依赖优化](https://vite.dev/config/dep-optimization-options)和 [Node 子进程](https://nodejs.org/download/release/latest-jod/docs/api/child_process.html)的官方说明。
