# 科研工作台优化计划（2026-10-01 调整）

本文件记录用户本轮确定的工作包，优先于旧 `IMPLEMENTATION_PLAN.md` 的包名与顺序。默认使用 macOS、可信用户与已登记服务器，继续使用现有 Python；不创建虚拟环境，不迁移历史研究数据。

执行顺序为 **A → C1 → B → C2 → D 发布验收**。C2 及用户追加的历史清理/目录命名、外观主题补充已完成本地与隔离验收；下一包为 D，不在本轮自动启动。D 的空工作区演练随每包进行，完整可移植设置与真实服务器闭环独立验收。每包更新交接及未验证事项；真实集群闭环须单独记录精确 job ID、程序结束和数值证据，模拟结果不能代替。

产品定位：面向有 DFT 基础的研究者，从结构到可复用、可比较结果的小型工作台。评价重点是用户能否独立完成任务、理解当前来源/输入版本/下一步，以及异常后能否继续。开发者的操作熟练度不替代首次使用验收。

## C1 已交付边界

- 主导航收敛为结构、计算流程、计算配置、运行与监控、结果与后处理。服务器、来源和派发合同沿用现有实现。
- VASP 的物理参数/继承与 k 点/赝势/文件审查在同一页面内分组，只有一个当前节点选择；沿用草稿数据与参数合成逻辑。
- 审查内容后紧邻确认框与冻结动作。修改有效输入立即使旧预览与确认失效；冻结包独立保存。
- “用此版本准备运行”明确携带当前节点和精确冻结 ID。普通入口只有唯一可用版本时自动选择；多个历史版本由用户选择；指定版本不可用时不换成其他记录。
- 单节点/计算链统一从运行与监控进入，执行范围明确选择。复用历史来源、程序匹配、额度、UNKNOWN 核查和提交一次保护保持。
- Wannier 来源、通道、参数与 `.win` 在计算配置内；到运行审阅只确认资源和脚本，两个视图共用同一组件状态。参数迭代定义与冻结表同样进入整批审阅。
- 合并重复项目头，项目操作/路径按需展开；画布工具只在流程页；任务栏默认收起；短显版本身份，保留完整值。
- 验收使用 1280×720、1440×900；空工作区实际导入、配置、审查、冻结、返回修改和版本交接。隔离 API 禁用远端操作，不启动 worker。

## B 本轮具体交付

1. 冻结清单/请求/结果文件协议及 doctor/check/run 行为；输入角色与结果单位、来源、限制统一表达。
2. 提供可独立运行的结构体积与元素统计模板、fixtures 和 CLI 测试；复制改名后安装/运行无需改主体。
3. 通用 JSON Schema 表单与本地/远端执行适配；先完成本地和模拟远端，再迁移首批算法。
4. 扩展管理负责依赖/启停/卸载；结构和结果页只显示当前可用动作。不适用和缺依赖分别说明，历史报告保留。
5. 覆盖多输入、多产物、超时、失败、安装与卸载；真实远端计算仍需专门授权及证据。

本地与模拟覆盖已完成，首批算法和通用比较入口已迁移；复制模板改名后可从目录/ZIP 安装、运行和卸载，无主体修改。详细协议和验收证据见 `extensions-b/`。旧 v1 接口保留历史兼容，不作为新扩展开发入口。

## C2 已交付边界

1. 先形成结果工作区：所选结果摘要、单位、程序/收敛证据、冻结输入与来源；待处理事项给出下一动作，避免仅堆叠报告。
2. 统一普通 attempt/扫描 case 的可比性说明、绘图与比较、分析历史筛选；保留不同物理模型和不足证据提示，不自动给科学优劣排名。
3. 完善失败/断网/重启/UNKNOWN 的原位核查与继续操作，尤其独立分析的目录/日志/精确 job ID；人工恢复不得隐式重新派发。
4. 分组参数、视觉统一、长表格和首屏分块，减少来回滚动；不改变既有物理参数、冻结合同或研究数据。
5. 使用首次 SCF、复用上游重跑分支、结果分析比较三条任务，在两种验收尺寸检查键盘/错误定位/表单保留，再交给未参与开发的用户演练。

本地与隔离演练已完成：项目概览保留旧 UNKNOWN 的精确记录入口；三种模板建立独立流程草稿；所选结果分摘要、文件、后处理与证据，摘要打开只读本机小型快照，主动读取指标后缓存时间/来源。比较绑定当前选择，变化即清除旧结果；展示实际冻结输入差异，模型/原子数不明确时不建立能量趋势连线。参数分组、常用/高级字段、错误定位与选项保留已接入。分析创建回执中断通过原 ID 或历史核查恢复，不隐式重建。详细证据及边界见 `frontend-c2/ACCEPTANCE.md`。

## D 下一阶段执行边界

1. 先完成可移植启动与首次设置：已有解释器、数据/赝势/研究路径、端口冲突检查，配置可修正重试；不创建 Python 环境。
2. 整理服务器登记：已有 SSH 别名、PBS/Slurm、VASP/Wannier/MPI/环境路径、队列、远端工作区和脚本；示例与实际验收状态分开。
3. 在空数据目录、独立浏览器存储和测试端口从零走完三条任务，使用确定性模拟服务器检验中断/重启/资源等待/UNKNOWN 和提交一次。
4. 形成发布检查表、已知限制与可恢复升级说明；邀请 2–3 位未参与开发的用户独立操作。开发者自测不替代他们的任务完成记录。
5. 真实学校服务器闭环另行明确授权，只在所选主机做必要只读预检；记录精确 job ID、程序结束与数值证据，不能把模拟通过标记成服务器可用。

2026-10-04 D 本地与跨平台准备已交付，详见 [验收记录](release-d/ACCEPTANCE.md)。Windows 原生与独立用户操作尚未验收；模拟回执不作为真实服务器成功证据。

## C2 与 D 的验收目标

- C2 用三条任务整理界面：首次 SCF；已完成上游复用并重跑分支；结果分析和比较。项目概览显示待处理事项，结果同时显示数值/单位、收敛证据和输入来源；不同模型比较明确差异。
- 完整设置向导检查已有解释器、数据/赝势/研究目录、端口、SSH 别名、调度器、运行时与脚本，保存后可修正继续。
- 邀请 2–3 位有 DFT 基础且未参与开发的用户独立演练，记录任务完成、所需帮助、返回/滚动原因和异常恢复。避免以功能数作为发布标准。
- 断网/重启/繁忙/UNKNOWN 不丢草稿、不重复派发、不误报成功；计算耗时和等待集群资源不计入界面操作效率。

A 的原则是区分本次执行节点与依赖来源，历史结果冻结到具体 attempt；复用来源必须满足同项目/节点/主机、程序结束和必要收敛与文件合同。唯一合格且物理输入一致自动采用；多来源或输入差异须由用户显式选择。轻量检查不声明内容完全一致，原有冻结合同不在运行中升级或降级。保留输入科学审查、原文件保护、额度、revision 与单次派发检查。

B 的原则是扩展只依赖稳定文件协议、不导入主体内部模块、不读工作台数据库；复制模板安装后无需新增主体业务分支或专用表单。JSON Schema 表单按既定方案薄接成熟库，正式修改依赖前复核官方资料与锁文件。卸载保留历史产物与来源快照。

C 保持现有参数继承与草稿数据结构，避免一字段多个入口。D 继续使用登记解释器，通过空数据目录隔离；真实服务器验收另行获得明确授权。
