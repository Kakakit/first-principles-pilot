# DFT 工作台交互设计规范（测评建议稿）

本规范描述下一轮界面改造的可验收行为；不改变现有冻结、来源核验、额度或显式授权规则。页面应始终让用户回答四件事：**正在操作哪个节点、采用哪份冻结输入、依赖哪个 attempt、此动作会产生什么远端效果**。

## 信息架构与导航

| 一级位置 | 主任务 | 保留在当前视图的上下文 |
|---|---|---|
| 项目/流程 | 选择结构、节点、连线、扫描容器；查看进度 | 项目、选中节点、节点类型和直接上游 |
| 参数 | 编辑当前节点唯一生效的参数草稿 | 结构版本、继承来源、覆盖值、未保存变更 |
| 输入 | 选择 POTCAR/KPOINTS，预览实际 INCAR 并冻结 | 节点、上游、参数版本、文件 hash、错误定位 |
| 提交 | 审查冻结版、主机、程序、脚本、资源、来源并准备/授权 | 当前节点→bundle→attempt 的完整链和授权范围 |
| 结果 | 选择 attempt/case，比较状态与指标，查看文件、图和备注 | 当前结果集合、单位、来源、四层证据 |

从流程节点进入任一页应带 `project_id + node_id`；返回时保留当前节点和子页。顶部只保留项目、节点面包屑和当前任务的主要动作。扫描授权、单任务提交和 Wannier90 参数属于各自流程，不把无关表单同时铺开。

## 行为规则

1. **默认与继承。** 节点关联的最新冻结 bundle 可预选，但清晰标记版本、冻结时间和短 hash；若有多个有效版本或来源不唯一，要求显式选择。旧版本在“查看其他版本”中列出，不靠相同标题区分。参数页的值分“继承/本节点覆盖/默认”，任何可编辑字段只有一处生效入口。改变上游、关键参数、主机、运行时或脚本后标记预览失效，并保留已输入的文字与选择供重新审查。
2. **动作层级。** 每页只突出一个主动作：参数“审查输入”，输入“冻结”，提交“准备预览”或“确认授权”，结果“保存图/导出”。远端提交与整批授权必须在预览页展示完整影响范围；普通保存或切页不能暗中授权。危险操作使用独立确认区，不与“刷新/继续”并排同色。
3. **来源链。** 在提交与结果首屏显示 `项目 / 节点 / 冻结输入 / 上游 attempt / 当前 attempt`，每级可展开原始路径、完整 hash、审查时间和审查理由。上游候选按同项目、同主机、连接关系与必要文件过滤；每个候选显示程序结束、收敛和兼容检查，不能只显示 `COMPLETED`。路径和哈希允许复制；不要把长串放在主要阅读线上。
4. **状态语义。** 统一中文标签：“待派发、已准备、提交中、运行中、调度完成、失败、状态待核查、已暂停”；详情保留 `PENDING/PREPARED/UNKNOWN` 等机器原码。结果表分列调度终态、程序结束、数值收敛、科学审核；缺证据写“未验证/无数据”，不写“成功”。数值均显示单位和来源；不同 U/J 模型能量比较加限定说明，不自动推荐最优 U。
5. **加载与错误。** 点击后 100–200 ms 内给出可见反馈；超过 2 s 显示当前阶段和已耗时。远端任务至少分连接、定位文件、传输/核验、解析、应用阶段；未知进度用阶段状态而非假百分比。加载时禁用同一动作的重复触发，但保留页面浏览。断网、超时、空响应、服务错误与校验错误分开；给出可执行的重试、回到本机工作区或修正字段入口。服务恢复后可原位重试，不丢草稿。
6. **等待与刷新。** 慢请求完成后只更新其目标卡片，不重置其他选择。离开页面再回来保留最近成功结果、时间戳和“重新检查”入口；不要把尚在查询的能量参考写成最终“不可用”。刷新历史状态不隐式提交或重试 attempt。

## 三个关键流程

### 单任务提交

入口自动带当前节点；预览首屏卡片依次为“冻结输入与差异”“上游与证据”“主机、运行时、脚本与资源”“远端目录与本次动作”。DOS/bands 需要的 `CONTCAR/CHGCAR` 逐项显示存在性和所选 attempt。若当前选择是非 SOC 节点而运行时保留 `vasp_ncl`，在准备之前明确指出并要求改选或说明；最终仍以现有后端审查为准。`PREPARED` 不是调度提交，按钮文案用“准备后审查”与“确认提交”区分。

### Wannier90

把四步做成固定顺序：① 选 VASP-Wannier attempt 和 `.win/.amn/.mmn/.eig` 频道；② inspect 来源并显示来源哈希与文件位置；③ 能量参考/能窗/投影/路径编辑和相对→绝对换算；④ 预览并冻结 `.win`。频道切换时保留草稿但显式标记“来源已变化，需重新核验”；重复 inspect 可复用有效的成功结果，仍由提交前的后端哈希复核把关。PyW90 远端只读路径生成的等待阶段、DFT bands 同源性、段数与点数应在同一卡片呈现。

### 结果与比较

结果选择器支持普通 attempt 和扫描 case 混选；先展示状态表，再切换总能/每原子能量/磁矩/运行时间趋势。曲线只连接物理条件可比较且有明确单位的点，缺值留空、未收敛带标记；同一图中不同 U/J 模型按组区分且给出解释限制。图保存/PNG 导出与完整来源清单相邻；LCALCPOL 两端比较及人工备注作为结果详情工具，不再作为独立流程节点。底部任务日志折叠为抽屉。

## 视觉与可访问性基线

- 4 px 网格；常用间距 8/12/16/24 px，卡片内边距 16–24 px；表单标签和错误贴近字段。正文基准 14–16 px，一级标题 22–24 px，元数据不小于 12 px。
- 颜色只承载辅助含义，状态同时有文字/图标；正文与背景对比度至少 4.5:1，非文字控件边界至少 3:1。错误、警告、待核查不可只用红黄灰区别。
- 1280×720 视口：结果页首屏能同时看到结果身份、一个主图/表和关键四层状态；表格长列可横向滚动并固定首列/表头。窄屏把选择器移至抽屉，动作保持可见。
- 键盘可到达所有 tab、下拉、表格行和图控件；焦点清晰。图表有可读标题、轴单位、图例和对应数值表；截图/导出保留来源说明。

## 验收任务

用隔离 Si 新建、FeCr2O4 快照续算与 Wannier90、两 case 扫描重复本报告六条路径。记录点击到首次反馈、点击到可操作终态、关键导航/确认次数及错误恢复成功率。特别检查：DOS/bands 不会误选同名 bundle；错误运行时被明确提醒；冻结后提交页定位正确；扫描只在审阅整个 case 表和资源后才能授权；页面刷新与断网恢复不丢草稿；旧 `PREPARED` 失效时不可提交。真实远端提交仍需用户在界面审阅并授权。
