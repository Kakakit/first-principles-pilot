# DFT 工作台真实使用测评报告

日期：2026-09-28。对象：当前活动源码的本机网页，1280×720 视口。结论：核心输入审查、来源校验与过时预览保护已经可用；实际工作中最明显的阻力是跨页后上下文丢失、长时间远端操作缺少分阶段反馈，以及结果页首屏空间不足。提交链的安全约束应保留，同时把用户刚选定的节点、冻结输入和来源带到下一页。

## 方法与边界

- 新建任务使用隔离 `UX测评-Si` 工作区，从 `tests/fixtures/Si.POSCAR` 导入结构；研究结果使用 FeCr2O4 的 SQLite 备份及小型资源快照。两个工作区均在 `/private/tmp/dft-ux-review/`，原项目只读。API 包装器阻断 submit、authorize、resume、retry、delete、cleanup 等端点；未启动批次 worker。
- 通过真实浏览器完成操作，截图为交互现场；API 计时由服务端中间件记录在 api-timings.jsonl（原始验收资料保留在本机）。计时是单次请求墙钟时间，**不是**点击到页面可用的完整感知等待。因旧轮次没有逐点击埋点，下表给出可复核的关键动作序列，不虚构总点击数。输入文字、滚动和重复错误尝试未计数。
- 状态 `COMPLETED`、VASP 程序结束、数值收敛与科学审核是不同主张。本测评只检查界面如何呈现这些证据，不重判材料结论。

## 六条任务路径

| 场景 | 实际关键动作（每个箭头为一次导航或确认，非全部点击） | 实际结果与边界 |
|---|---|---|
| 1 新建 SCF | 新建项目 → 导入 Si POSCAR → 加 SCF 并连接 → 参数页编辑 → 输入页选择赝势、预览、冻结 → 提交页选冻结输入、诊断、资源预览、准备 | 输入校验展示错误及差异，冻结成功；服务器探测约 15.7 s；仅创建隔离 `PREPARED`，没有提交。画布侧栏的“旧版草稿（不参与参数合成）”易造成先填一遍、参数页再填一遍；冻结后提交页未自动选本次输入。见 旧草稿（原始验收资料保留在本机）、输入页（原始验收资料保留在本机）、诊断中（原始验收资料保留在本机）。 |
| 2 SCF → DOS/bands | 选研究项目的 DOS/bands 节点 → 输入页查看依赖和路径 → 提交页手选冻结 bundle → 再手选上游 SCF attempt | DOS 预览正确指出需要 `CONTCAR/CHGCAR`。bands 可显示路径 hash，但上游选择需再次完成。提交页可选 25+ 项跨阶段 bundle，多条同名；选择 DOS bundle 后才显示 `25101.node01 · scf`。同页保留先前 `vasp_ncl` 运行时，用户需要主动核对。这里只走到依赖选择，未准备或提交研究任务。 |
| 3 Wannier90 | 选已完成 VASP-Wannier `25104.node01` → discover `.1/.2` → inspect `.1` → 查询能量参考 → 修改 `num_iter` 和相对能窗并应用 → 选同源 DFT band `25114.node01` → 生成、应用 k 路径 | `.win` 实际得到 `num_iter=500`、`dis_win_min=3.179381397 eV`，能量参考 E_F=6.179381 eV；路径 9 段、每段 40 点，有 KPOINTS/path hash。大矩阵仍在远端。切频道会卸载当前来源，需要再 inspect；几次远端请求只显示笼统“处理中”。未冻结新 Wannier 输入、未提交。见 发现中（原始验收资料保留在本机）、路径中（原始验收资料保留在本机）、已应用（原始验收资料保留在本机）。 |
| 4 结果 | 研究项目 → 结果分析 → 任务/文件 → 交互图选择 Cr dxy、调整能窗 → 保存图并导出 PNG | 文件来源和图形操作可用；缓存曲线请求约 0.09–0.13 s。首屏顶部导航与底部任务面板共同挤压主内容，关键来源和图形操作需滚动；未对图作物理解释。见 首屏（原始验收资料保留在本机）、保存图（原始验收资料保留在本机）。 |
| 5 参数扫描 | 隔离 Si SCF → 新增迭代节点 → ENCUT 400:50:450 → 预览两项差异 → 冻结 | 得到两个 case 和稳定定义 hash；授权按钮保持禁用，没有授权。整批区继续复用单任务的“先选择冻结输入”说明，长 hash 和 `FROZEN/PENDING` 直接露出。见 扫描（原始验收资料保留在本机）。 |
| 6 恢复与异常 | 人为断开隔离 API → 刷新；恢复 API；改已准备任务的作业名 | 断网展示原始 `Unexpected end of JSON input`，缺少可操作恢复；恢复服务后可继续。作业名变化使旧 `PREPARED` 预览失效、提交按钮禁用，这是正确保护。见 断网（原始验收资料保留在本机）。缺失上游时输入预览会指出依赖文件；未覆盖真实网络断续中的远端提交恢复。 |

## 等待与性能证据

| 请求 | 本次样本 | 服务器墙钟时间 | 用户感受到的主要问题 |
|---|---:|---:|---|
| 输入预览 | 4 | 中位 0.005 s | 快；错误仍需和具体字段紧邻 |
| 服务器 probe | 1 | 15.69 s | 只见通用处理中；无主机/阶段反馈 |
| 执行 prepare | 1 | 7.31 s | 应显示正在核对的输入、来源和远端路径 |
| 扫描预览/冻结 | 各 1 | 0.015 / 0.041 s | 快；授权范围需醒目 |
| 曲线 series | 5 | 中位 0.108 s，范围 0.093–0.131 s | 缓存曲线操作流畅 |
| Wannier discover/inspect | 各 2 | 中位 7.56 / 32.58 s | 尤其 inspect 缺少分阶段进度 |
| 能量参考 / PyW90 路径 | 各 1 | 17.66 / 27.23 s | 等待时反馈笼统，短暂出现“能量参考尚不可用” |

这些值不代表所有主机、冷缓存、真实批次或长期设备耗电。SSH 与远端解析构成主要慢请求；本次不能把其全部归因于前端。

## 问题清单与验收

**P0 · 易误操作或阻断**

1. **节点/输入/运行时上下文未贯通。** 复现：选 DOS 节点进入提交页，冻结输入仍从全项目 25+ 条中查找，含重复标题；手选 DOS 后保留 `vasp_ncl`。证据：DOS 提交页界面记录（原始验收资料保留在本机）；源码 `src/ExecutionPanel.tsx`、`src/ServerPanel.tsx`。影响：可能选错冻结输入或程序，后端校验虽可能拦截，却增加试错与漏检机会。原因把握：高，前端选择状态未以当前节点预填；并非证明会错误提交。建议：当前节点只显示关联的最新冻结版本并默认选中，显示 hash 短码；运行时按冻结 INCAR 校验并显式提示冲突，保留人工确认。验收：从 DOS/bands 节点进入提交页，首屏显示节点、唯一当前冻结版、上游 attempt、`vasp_std/ncl` 适配结果；同名旧版可展开查询但不自动代入。
2. **断网错误不可恢复。** 复现：隔离 API 停止后刷新结果页；出现原生 JSON 解析异常。证据：断网截图（原始验收资料保留在本机）。影响：用户无法区分服务离线、空响应或结果损坏，也看不到重试入口。原因把握：高，网络/非 JSON 错误直接渗到页面。建议：统一请求错误映射，保留当前内容，显示服务状态与“重试/查看本机工作区”。验收：停服务、空响应、超时分别给明确提示；恢复服务后一键重试，不丢表单草稿。

**P1 · 高频效率**

3. **两套参数入口造成重复劳动。** 复现：画布侧栏填写“旧版草稿”，参数页仍需独立填写。证据：侧栏截图（原始验收资料保留在本机）。影响：误以为已参与合成，浪费输入时间。原因把握：高，界面明确标注“不参与参数合成”但仍提供编辑。建议：把旧入口变只读摘要与“打开参数页”，或让其真正与主表单同源。验收：任一可编辑参数只存在一个生效源；输入页预览逐项对应。
4. **远端慢操作反馈不足。** 复现：probe、Wannier inspect、能量参考、PyW90 路径；各约 8–33 s。证据：probe（原始验收资料保留在本机）、inspect（原始验收资料保留在本机）、路径（原始验收资料保留在本机）与计时记录。影响：用户无法判断进度、易重复触发或误认失败。原因把握：高（反馈），中（性能成因）。建议：按“连接主机/读取小文件/校验大矩阵 hash/解析/应用”展示阶段、已耗时、取消仅对可取消任务启用；请求完成前不以“尚不可用”表达最终状态。验收：所有超过 2 s 的请求有即时、明确的阶段反馈，重复点击被抑制；终态和中间态文案可区分。
5. **提交页与扫描授权文案复用失焦。** 复现：冻结两 case 后，整批区仍提示“先选择冻结输入”。证据：扫描截图（原始验收资料保留在本机）。影响：用户不清楚一次授权覆盖的范围和还缺什么。原因把握：高。建议：扫描专属授权摘要，列出 case 数、输入版本、主机、脚本、资源、来源与每次派发复核；逐项缺失提示。验收：授权按钮旁可见完整授权范围，所有未满足条件各自指向设置处。

**P2 · 视觉与一致性**

6. **结果首屏有效高度不足。** 复现：1280×720 结果页保留顶栏、次级导航和底部任务面板。证据：首屏截图（原始验收资料保留在本机）。影响：状态表、图形及来源都落在折叠线下，高频分析需反复滚动。原因把握：高。建议：任务面板默认收起或改为可拉抽屉；结果页独立三栏结构（选择/图/证据），工具栏吸顶。验收：该视口能同时看见所选结果身份、主要图和关键状态；鼠标/键盘可展开详细证据。
7. **英文状态和原始 hash 与中文任务语言混杂。** 复现：扫描显示 `FROZEN/PENDING` 和长 hash。证据：扫描截图（原始验收资料保留在本机）。影响：阅读负担与主要动作竞争注意力。原因把握：高。建议：中文状态为主、英文原码作 tooltip/详情；hash 首屏短显、复制完整值。验收：同一任务的状态词一致，展开证据后可取得完整原值。
