# 扩展运行位置与 Python 环境 · 2026-10-06

已实现“默认环境＋扩展覆盖”。同一扩展按清单声明支持本地、服务器或两边；原 execution.locations / preferred_location 和服务器直接执行、调度方式保留。科学算法仍只在独立 CLI 中，宿主负责解释器选择、来源、SSH、文件传输和回执。

## 使用

1. 打开“扩展管理”，通过“本地运行 / 服务器运行”筛选。双位置扩展会出现在两类中。
2. 在“本地默认 Python”保存已有绝对路径；“沿用工作台解释器”清除本地默认。此设置只影响扩展子进程。
3. 在“服务器默认 Python”保存主机的已有解释器和工作区。旧远端登记直接作为默认环境，不迁移、不自动换主机。
4. 展开扩展卡片的“Python 环境 · 默认或单独指定”，选择本地或具体服务器；“单独指定 Python”保存覆盖，“使用默认环境”清除当前范围覆盖。本地、不同主机、不同扩展分别保存。
5. 保存后点击“检查所选环境”，查看路径、Python/程序/依赖版本和缺失原因。服务器只执行 doctor，不运行分析或提交作业。启用状态与环境状态分开，参数始终可以先编辑。
6. 在结构或结果页确认选定解释器，填写选项。修改环境后点击“刷新环境设置”，重新检查或预览；旧选择无法继续创建分析。创建后环境、服务器和参数冻结，实际 doctor 版本记录随分析保存。旧历史缺解释器显示“未记录”。

TB2J 默认在来源服务器直接运行，可单独指定该服务器的 TB2J Python，不填写调度核数或探测节点。小输入可用本地环境；超过 10 MiB 的输入继续提示远端运行。直接调用解释器绝对路径，[无需 activate](https://docs.python.org/3/library/venv.html#how-venvs-work)。软件不安装、升级或创建环境。

接口和字段见 [v2 协议](PROTOCOL.md#环境-api-与兼容)。运行路径保存在本机数据，不写进包或同步 GitHub。
