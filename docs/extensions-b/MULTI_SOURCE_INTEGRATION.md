# 多来源后处理接入：EOS 扩展开发交接

宿主已支持一次分析最多 64 个明确来源，含当前结果；计算项目不需要重建或导入。EOS 的能量/体积解析、异常判断、模型拟合、单位和绘图属于独立扩展。本包只修改通用宿主能力，不内置 EOS 算法或自动提交计算。

## 使用入口

“结果与后处理”选择一个已有任务 → “运行后处理”选择启用的扩展 → “批量选择已有任务”。按节点名称、作业号、输入备注或服务器搜索，逐项勾选或全选当前筛选结果，再“采用这批来源”。当前任务固定为来源 1，原有顺序保留，新增任务按列表顺序加入；取消不修改选择。总数受扩展清单限制，超过限制不能全选，没有默默截断。附加来源仍可逐个调整/移除。

列表仅包含本项目已登记、未回收且使用受控 attempt 路径的任务，包括较早的任务。阶段或 SSH 主机不适用的任务显示原因并禁止勾选；程序状态、必需文件、收敛证据继续在采用后及执行前核验。列表与选择均不会运行分析、创建远端目录或提交研究任务。

## 独立扩展最小适配

从 `extension-templates/structure-statistics` 复制独立包，并使用随宿主更新的 `protocol/manifest.schema.json` 和 `protocol/request.schema.json`。旧副本中的 `maxItems:8` 也要更新；仅修改扩展的清单上限不足以通过旧请求 schema。

清单相关片段（与包内其他必要字段合并，文件大小和超时由扩展自行设定）：

```json
{
  "contexts": ["attempt"],
  "stages": ["scf", "relax"],
  "sources": {"min": 4, "max": 64},
  "inputs": [
    {"role": "outcar", "title": "VASP OUTCAR", "names": ["OUTCAR"], "max_bytes": 10737418240},
    {"role": "structure", "title": "实际 POSCAR", "names": ["POSCAR"], "max_bytes": 262144}
  ],
  "evidence": ["COMPLETED", "vasp_timing", "ediff_reached"],
  "execution": {"locations": ["ssh"], "preferred_location": "ssh", "timeout_seconds": 600}
}
```

`min=4` 是接入示例，扩展根据支持的拟合模型确定点数要求。结构优化的最终体积与离子收敛需要从实际输出核验，不能用输入 POSCAR 的体积代替最终晶胞；宿主的程序结束/电子证据不证明离子收敛或物理可比性。扩展自行检查计算设置、能量定义、原子数归一化与可比性，保留剔除理由，不将拟合完成表述为物理验证通过。

CLI 协议保持 `doctor → check --request → run --request`，完整字段见 [协议 v2](PROTOCOL.md)。请求 `inputs.<role>` 每项含 `path/name/source_id/size_bytes`；按 `source_id` 关联 `sources` 中的具体 attempt、节点、服务器和证据，不能用目录名猜来源。可选输入可能少于来源数量，不能按数组下标配对。不要导入宿主 backend、访问数据库或自己 SSH 到任意目录。

## 大文件与结果传输

现有 SSH 直接命令行路径可以复用：所有 attempt 来源必须位于同一来源服务器。宿主在该服务器的独立 `analyses/<analysis_id>/inputs/` 普通复制所需文件，核对大小/修改时间，扩展只读取这些独立副本。OUTCAR 不先下载到本机，不哈希整份大文件。复制会占用服务器分析目录空间，当前并非零复制读取。

扩展在来源服务器逐文件解析 OUTCAR，只向请求 `output_dir` 写整理后的表格、CSV、拟合曲线、图和最小证据。不要把完整 OUTCAR 放入结果 artifacts。result JSON 与每个回传产物不超过 10 MiB；更大产物留在远端并显示路径。本机输入超过 10 MiB 会被阻止并提示远端运行；同主机约束不做跨服务器隐式迁移。选定环境必须是服务器已登记的 Python，不自动安装依赖。

可保存每点的实际 attempt/作业号、使用的能量/体积、单位、取值行或步骤、程序/收敛证据及剔除理由；这些由扩展科学算法生成。宿主冻结来源、选项、包版本与环境，保留分析历史及原任务，不根据扩展结果改写原计算证据。

## 宿主 API

- `GET /api/extension-host/sources?project_id=...` 返回 `{max_sources:64,attempts:[...]}`：本机任务元数据、可读节点名、备注、阶段、主机、作业号与状态。没有远端文件内容，不刷新/扫描服务器目录。
- `POST /api/extension-host/context`、`check`、`preview`、`analyses` 的 `sources` 最多 64 项；原请求形状不变。每项仍为 `{kind:"attempt",attempt_id:"...",files?:{角色:"文件名"}}`。
- 空列表、65 项、重复来源、其他项目来源拒绝；具体扩展的 min/max、文件和证据限制继续生效。刷新/创建重新核验，不自动替换来源。UNKNOWN 只核查原分析，不重执行。

原 1–2 来源扩展与历史记录无需迁移，也不会自动扩大它们的来源数量。后续扩展只要声明清单、更新包内 schema 并实现独立 CLI，无需再修改宿主 EOS 专用代码。
