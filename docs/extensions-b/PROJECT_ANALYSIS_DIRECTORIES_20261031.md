# 扩展分析随计算项目保存 · 2026-10-31

新建远端扩展分析统一保存在 `项目目录/analyses/<analysis ID>/`。每次分析仍有独立目录，包含冻结扩展、输入副本、请求、脚本、日志和 `outputs/`；服务器生成的交互展示继续位于该分析的 `presentations/` 内。已有来源关联继续记录精确 attempt，不依赖目录名称猜测来源。

## 目录选择

1. 有计算来源时，优先使用第一个来源 attempt 已冻结的 `remote_project_path_absolute`。更改当前项目目录或服务器默认工作区，不会把旧来源的后处理放到另一处。
2. 较早的 attempt 缺少项目字段时，仅从既有 `flows/<flow>/stages/<stage>/attempts/<attempt>` 布局恢复项目父目录。多来源分析以第一个计算来源的项目位置为准。
3. 没有可恢复的来源项目路径时，使用当前项目设置：单服务器项目目录覆盖优先，其次是通用工作区与项目标识，并保留旧项目的 `material-projects/` 布局。
4. 不属于项目的独立结构分析可使用明确登记的工作区；若只剩 `$HOME` 或 `/`，提示先指定项目或工作区，不再创建 `$HOME/analyses`。

预览说明及脚本显示目标位置；实际子目录使用生成的 analysis ID。分析根目录参与预览绑定，并写入新分析记录的 `remote_analysis_root`。启动脚本与远端 staging 共用该冻结值；预览后目标变化会要求重新预览，排队后修改设置不会改变已确认位置。

此改动属于 main 的通用宿主，未修改独立扩展包、科学算法或扩展协议。已运行分析仍按记录中的 `remote_dir` 读取、核查和生成展示；不会重新计算、改写路径或迁移服务器旧文件。旧预览需重新生成，尚未启动且没有冻结目录的旧记录拒绝派发，需重新预览新建；已启动的 UNKNOWN 继续只核查原回执。
