# Windows SQLite 连接释放修复 · 2026-11-13

## 问题与行为变化

SQLite 连接的 `with connection` 上下文只提交或回滚事务，不关闭连接。
Windows 上，启动器派发检查、历史索引、文件收集、数据集上下文、节点引用检查、
本地回收和取消回执日志可能在返回后仍占用数据库文件，直到垃圾回收才释放。

这些入口现用 `contextlib.closing()` 显式关闭连接；写入入口在其内部保留原事务上下文，
正常完成仍提交，异常仍回滚。回收逻辑的对象选择、隔离目录与失败恢复语义不变。
只读 URI 使用 `Path.as_uri()`，避免工作目录里的 `#` 等字符被误解为 URI 片段。
没有数据库迁移，没有远端提交、取消或删除操作。

## 回归与测试兼容性

- 新增 7 项跨平台生命周期测试：保留连接对象的强引用，检查连接已关闭，使 Linux
  也能发现被垃圾回收掩盖的泄漏；Windows 另验证数据库可立即重命名。
- 覆盖正常读取、非法数据库、扫描异常、提交、回滚、取消回执持久化和计划暂停。
- 关闭相关测试夹具自己的 SQLite 连接，避免清理临时目录时产生假失败。
- 图标格式验证保留在所有平台；macOS bundle 的符号链接验证在 Windows 跳过。
- 两个符号链接用例只在 Windows 实际返回权限错误 1314 时跳过；其他异常仍失败。
- 规范化用于构造非法结构/CRLF 样本的测试夹具换行；原始字节保真验证保留。
- 新增 Windows/Linux CI 工作流 `sqlite-lifecycle.yml`，验证本地功能与宿主取消回执。
  Linux 远端调度器模拟和私人集群验证不在该本地工作流中。

25 skipped；上轮 main 为 952 项、32 failures、435 error entries、22 skipped。
条目可能包含同一测试的业务/清理/子测试错误，不能直接相减得到独立缺陷或通过数。

唯一根因，亦不能据此宣称 Windows release 已验收通过。依赖审计升级未混入此修复。
