## A. 可见错误与参数中心

### A1. 畸变扩展适用性及界面清理（小，约 1–2 个开发日）

- 在运行前选结构来源、中心元素、配体、配位数、搜索半径；没有对应元素或配位条件时显示“不适用”，不调用分析程序。不得再对 Si 结构套用 FeCr₂O₄ 默认配置。
- 将程序状态、适用性和科学审核状态分开；“计算成功但未审核”正常展示。
- 删除界面中的旧阶段代号和“将在某阶段接入”文案，保留必要的功能边界说明。
- 验收：Si fixture 显示不适用；显式 Fe/Cr/O fixture 产生 CSV/JSON/Markdown；结果原文件不覆盖。

### A2. VASP 参数中心（中至大，约 4–7 个开发日）

- 后端维护一份 tag 目录，前端只读取；常用参数强类型，官方已知低频参数用单行 passthrough，自定义未知参数要求显式确认。保存目录快照来源与确认级别。
- 首批：`ISTART`、`ICHARG`、`LWAVE`、`LCHARG`、`ISYM`、`ALGO=All`、`NBANDS`、`NEDOS`、`EMIN/EMAX`、`LREAL`、`LASPH`、`NCORE/KPAR`。展示来源、单位、VASP 版本与适用节点；不自动填物理数值。
- 重启与依赖合同优先于自由输入：需要 WAVECAR/CHGCAR 时核对真实文件和兼容性；DOS/能带等受控节点清楚显示锁定值与原因。禁多行、重复 tag、冲突和不安全输入。
- 验收：前后端同一物化结果；冻结输入保留 tag 来源与校验级别；旧 1.0 受支持输入不发生无提示变化。

## B. 扩展开发合同与结构对称性

### B1. Extension SDK（中，约 3–5 个开发日）

- 基于已有 `_template`，定义输入选择器、适用性检查、输出 schema、依赖、运行环境、副作用、入口命令、测试 fixture 和 validator；旧扩展先经适配器继续读取。
- 扩展安装与启用明确分开；只有通过 validator 且用户明确启用的扩展进入运行清单。失败保留独立 analysis record；不修改计算原文件。
- 验收：原两项扩展仍可运行；缺依赖、结构不适用、运行失败与待科学审核显示不同状态。

### B2. POSCAR/CONTCAR 只读对称性（中，约 2–3 个开发日）

- 用当前登记 Python 的 pymatgen/spglib 计算空间群、等价原子、Wyckoff 位等；记录输入 hash、`symprec`、`angle_tolerance` 和库版本。
- 提供 0.001/0.01/0.1 Å 比较，不替换结构；明确这不是磁空间群分析。
- 验收：标准结构、轻微扰动、截断结构与不同容差的稳定结果，原文件字节不变。

## C. VASP 到 Wannier90 的两节点数据链（大，分两个里程碑）

### C1. 接口数据准备（约 5–8 个开发日）

- 从已完成 SCF 选择同主机父 attempt。现有 SCF 写 CHGCAR 而不写 WAVECAR；先确定固定电荷接口计算的 `ISTART/ICHARG` 合同，逐项核对结构、POTCAR、泛函、k 网格、`NBANDS`、自旋与 U/J。
- 编译指纹必须确认 VASP 含 VASP2WANNIER90。结构化编辑 `.win` 的用户字段，保护 `unit_cell`、`atoms`、`kpoints`、`mp_grid`、`num_bands` 等由 VASP 决定的字段；若已有 `.win`，提交前核对其 k 点与本次 VASP 完全一致。
- 输出 bundle 记录 `.win/.amn/.mmn/.eig` 和可选文件、父 attempt、spin、k 点数、程序版本与远端 hash。大型矩阵只在服务器内部复核，不回传超过 10 MiB 的文件。

### C2. Wannier90 执行与验收（约 6–10 个开发日）

2026-09-25 用户将本轮范围收窄为 Wannier90 参数设置及提交流程。局域化质量分析、DFT–Wannier 能带叠图和替用户完成真实提交不属于本轮交付；真实作业由用户核对预览后执行。

- 新节点消费冻结 bundle；复用现有 Wannier90 parser 与 tag registry。主机 profile 明确可执行文件、串行/MPI 模式、launcher、环境及模板；不猜命令。
- 程序结束、局域化收敛、DFT–Wannier 一致性和物理适用性分层。显式绑定非自旋单组、共线 `.1/.2` 通道或 SOC/spinor 单组；用户提供的真实 VASP 接口文件已验证这三种命名与 `spinors` 形式。局域化质量另由 Wannier90 输出评估。
- 先在一台有明确 Wannier90 运行时的主机做只读发现、输入审查和小型真实闭环；每次提交先实时容量预检并取得明确单次授权。其他主机逐一增加，不用历史脚本推断可用。

## D. 参数扫描与折叠 case（大，约 8–12 个开发日）

- 容器节点保存参数维度和冻结 case 表。首版笛卡尔积，最多 4 维；Decimal 生成起点/终点/步长，预览全部组合和作业数，硬上限 64 case。
- 先定义稳定 case ID、case 参数快照、单次重试和结果来源。每个 case 在同一阶段目录下生成独立 attempt；容器不改变唯一远端目录布局。选择并提升 case 时保留父扫描与来源 hash。
- 复用现有单任务提交和全局/单主机额度；UNKNOWN 占额度且不重投。首版不使用 job array。U/J 扫描仅做比较，不自动选“最优 U”。
- 验收：组合与边界值、重启恢复、部分失败、UNKNOWN、case 提升、折叠画布与完整结果追溯。
