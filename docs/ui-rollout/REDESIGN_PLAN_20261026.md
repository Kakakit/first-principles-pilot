# 浅色科研工作台：前端整改方案

日期：2026-10-26。状态：规划，未实施正式界面改动。

用户已选择：中性底色、绿色少量强调、图表和内容突出。沿用现有工作台功能与导航语义，以体验、稳定性和轻量性为优先。

## 诊断依据与结论

依据 refactoring-ui 的层级、间距、减弱次要元素、减少容器嵌套等方法，检查本机运行页面及相关 CSS。现场观察覆盖 Cr2FeS4 的项目流程、计算配置、结果与后处理三个页面，窗口为 1280×720；没有覆盖所有弹窗和异常状态。以下坐标是当前样例的近似值，不代表所有数据状态。

此前整改已统一字号、色阶、间距和控件，但这些只能建立一致性，无法单独证明构图和视觉层级已经做好。当前主要问题是首屏空间分配、重复信息、过多同等强调的容器，以及历史样式叠加。继续只调圆角、颜色和阴影，收益有限。

| 页面 | 当前可见问题 | 整改方向 |
| --- | --- | --- |
| 计算配置 | 多层上下文、步骤导航、说明和搜索把第一排参数推到约 y=462；每项重复最终值、继承状态、恢复操作 | 合并上下文；紧凑分组表单；继承信息按状态显示；帮助就近按需展开 |
| 项目流程 | 左栏约 192px、右栏约 384px，画布剩约 700px；多层顶部条占高；节点类型色、草稿/结果/链状态同时争夺注意力 | 降低工具栏高度与色彩强度；突出选中节点和当前操作；状态按语义分层 |
| 结果与后处理 | 上方管理、反馈留白与四格证据区占据主要空间，数值到约 y=500 才出现 | 结果或明确空状态先出现；证据保留摘要，详情可展开；记录管理退居次要 |

代码关联：`src/ui-system.css` 的广域控件规则与 `src/workbench.css`、`src/calculation-ui.css`、`src/results-ui.css` 的局部规则并存；`src/style.css` 保留历史样式。参数搜索实际铺满、项目标题呈输入框外观，与部分局部规则意图不符，应在实施时检查 computed styles 确认覆盖来源。`--ui-muted` 与 `--ui-subtle` 同指向一个颜色，次级与辅助文字的角色尚未真正分开。结果样式存在后续重复覆盖，继续追加补丁会提高维护成本。

## 视觉目标

- 页面背景采用低饱和中性灰，主要工作面为白色；减少大面积灰绿铺底。绿色主要用于当前选择与主操作。
- 正文、字段、辅助说明有明确层级；主要靠布局、字重和间距区分，不靠不断缩小文字。正文和字段以 14–16px 为起点，页面标题 20–24px，再以真实页面调整。
- 用分组留白与少量分隔线组织内容；卡片用于独立对象，不给每一个普通参数重复套卡片。
- 结构模型、曲线和计算数据成为视觉主体。空状态说明下一步，不填入装饰图或假数据。
- 保留可辨认的输入边界、键盘焦点和选中状态；辅助文字仍须可读。类型色与执行状态色分工，避免仅凭颜色传达含义。
- 桌面科研工具优先：压缩导航及重复信息，保留操作目标尺寸。窄屏检验用于确认面板可收缩，不强行把整个流程画布变成手机布局。

## 实施顺序

### 包 1：计算配置页样板

先完成一个真实、可操作且具有明显视觉改善的页面。选择常用 SCF 参数组，覆盖继承、局部覆盖、长名称、错误和保存中状态。

建议页面顺序：全局导航 → 单行节点/编辑范围上下文 → 配置步骤 → 参数分组与搜索 → 参数内容。将导入等低频操作归入紧凑工具区；删除重复组标题和无内容反馈占位造成的空洞。

参数用对齐的标签、值、单位和轻量来源提示组织；普通标量可成两列，长文本与复杂控件独占一行。继承值直接出现在输入位置，来源以简短标记提示；只有真实覆盖时显示“恢复继承”。说明与来源按需展开，校验错误紧邻对应字段。保留已有计算与编辑语义。

先用灰阶验证层级，再加入绿色和状态色；在同一数据、同一窗口下做前后对比，实际检查输入、保存、撤销与切组。样板达到目标再推广，避免一次重写全站后才发现方向不对。用户的视觉反馈可直接调整样板，不引入软件使用时的新审核步骤。

主要涉及 `ParameterPanel.tsx`、`calculation-ui.css` 及其上下文组件。目标：1280×720 下常用参数第一排进入约 y=280–320 区域，至少完整显示两排常用标量；这是一项待验证的布局目标，复杂控件不强行压缩。

### 包 2：提取共享样式，整理应用外壳与流程页

从已验证样板提取页面标题、上下文条、分组标题、字段、状态标记和反馈样式。按“令牌 → 基础组件 → 页面布局”明确归属；迁移一个组件就清除其失效旧覆盖，避免再追加一个全站覆盖文件。保留主题导入格式，通过语义映射兼容旧主题。

流程页合并冗余工具条，项目名平时作为标题、编辑时才呈现输入控件。右栏按所选对象聚焦摘要及下一步，允许收起且保留调宽行为；不通过缩小所有文字换取画布面积。节点使用中性底色、少量类型标识和清晰选中轮廓，主状态直接表达当前任务，草稿、历史结果和计算链状态分别归类说明。

减少右栏多层嵌套滚动，避免帮助提示与节点重叠。保留原画布视角、选择和导航恢复。主要涉及应用外壳、`workbench.css` 与共用 UI 样式。

### 包 3：结果与后处理、运行监控

结果页上方保留紧凑节点/记录选择，随后展示已有缓存结果、关键数值或有行动提示的空状态。调度终态、程序结束、数值收敛和物理证据仍分别呈现：正常时用简短摘要，异常时明确突出，详细依据就近展开。

把备注、记录整理等放到次要操作区，清理无内容时的固定反馈留白。保护最近新增的远端保存位置、完整文件路径和复制入口，在相关结果或产物附近保持容易找到。

后处理宿主围绕“选分析 → 配参数 → 运行/看结果”安排主次；高级环境信息按需查看。运行监控优先展示当前任务和恢复动作；减少重复状态说明。此次只改 main 的宿主界面，不在兼容快照中改扩展源码。

主要涉及 `NodeResults.tsx`、后处理宿主、监控组件及页面 CSS；实际文件范围在实施前按组件依赖确认。

### 包 4：其他页面与收尾

将已验证组件应用到结构、服务器、设置、空状态和弹窗，不重新发明每页样式。检查长中文路径、长节点名、多项目、加载、错误、无结果和大流程状态。删去已失效的重复选择器，记录最终组件样式归属。

## 验收方式

视觉验收以真实页面为准，不能只用 token 数值或构建通过代替：

1. 同数据、同窗口的前后对比：1280×720 为主要约束，补查 1440×900；具备真实缩放入口时检查 125%，未实测则明确记录。
2. 首屏能快速辨认当前节点、编辑范围、主要内容和当前主要操作；正常状态不被警告样式、边框和徽章淹没。
3. 内容分组的外间距明显大于组内间距；次要说明不与主要值同等突出。页面以一个主滚动区为主，画布及必要长列表保留独立滚动。
4. 关键路径可操作：切换节点/记录、编辑及恢复继承、保存/撤销、查看结果、复制输出路径、返回画布。错误提示可见，快捷键与焦点正常。
5. 运行受影响的前端交互检查、类型检查与构建；纯视觉调整不新增镜像 CSS 的测试，也不因未改变的后端业务重复全量回归。

## 轻量性与稳定性边界

不新增大型 UI 框架、远程字体或持续动画。复用现有图标、图表和组件；隐藏页保留已有卸载与按需加载策略，避免为了预览同时常驻多个三维视图或结果图。

界面重排不得增加请求频率、自动触发远端结果更新、修改提交合同或加入哈希/审核门禁。稳定性反馈采用紧凑状态与就近错误，不能简单删除用户恢复操作所需的信息。实施前后在同一页面往返场景观察请求与视图释放；只有发现新增问题才扩大性能排查。

本轮只完成规划及本机页面观察；没有改正式界面，没有触发远端任务或结果刷新。美化效果尚未实施、也尚未验收。
