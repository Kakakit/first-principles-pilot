# 主程序稳定性与入口整理 · 2026-11-03

依据“Astra审阅优化”聊天最后一轮的四项风险及导航、草稿建议实施。本轮只修改主程序前端，未增加依赖或审核步骤。

## 已修复

- 任务导航使用统一的项目、节点、运行记录、页面和运行范围状态。运行页跳转结果页携带确切 attempt ID；往返保留记录，换节点清除旧记录。问题记录的跨项目跳转也复用相同入口。运行页和结果页共用记录选择控件，摘要与详情依据同一选择，不再暗中显示另一个默认记录。
- 冻结输入选择直接使用已加载的设置同步更新主机和程序，不再为每次选择另发设置请求。服务器面板复用该设置，晚到的初始化回执也不能覆盖用户已修改的配置。Wannier 冻结输入的异步主机更新补上旧回执隔离。
- 运行历史、冻结输入和服务器设置分别加载、分别报错和重试。服务器配置失败不再阻止读取历史任务。读取按通道取消旧请求；离开页面取消读取，提交等已发出的操作不自动重试。
- `requestJson` 默认等待上限：本机查询30秒，远端文件读取120秒，修改或执行请求180秒；节点检测显式120秒。原有显式等待设置继续优先。超时会结束界面等待，不能解释为远端已停止。单任务提交失败或超时后查询同一 attempt ID，清除旧确认框并提示核查原任务；不自动再次提交。提交超时也通知绑定状态刷新。

## 入口与草稿

普通 VASP 计算配置分为“物理参数与继承”“计算来源与重启”“k 点、赝势与输入审查”。阶段预设和个人模板直接位于物理参数页，高级手动来源可在来源页选择。设置中移除第二套节点参数编辑器，原分类改为本机 POTCAR 库。

任务备注统一在结果页编辑；运行页保留任务状态、查看结果、取消和恢复，低频记录操作仍在管理区。配置、运行和配置子页仅挂载当前内容；链、扫描、Wannier 的隐藏视图也改为条件挂载，避免隐藏子组件继续请求。实际物理草稿保存在项目中，提交设置和配置子页选择由会话草稿恢复；确认和授权不进入该缓存。

会话缓存最多256项、估算文本容量8 MiB，按最近使用淘汰；项目或节点移出工作区后释放对应缓存。单项超过限额仍可在当前页面编辑，但不进入会话缓存。这个限额约束缓存内容，不代表浏览器总内存上限。

## 验证

- 前端全部169项测试通过，包括任务往返、旧回执失效、取消请求、缓存淘汰与项目/节点清理；TypeScript 与 Vite 生产构建通过。
- 隔离主程序页面使用合成项目、正式主题及 React StrictMode。服务器接口503时历史记录正常显示，关闭故障后可单独重试。
- 慢旧详情与快速切换不会覆盖新选择；从旧记录进入结果再返回，仍选中旧记录；跨结果节点后选中目标节点自己的记录。
- A/B 输入交替后，实际检测请求为 B 对应的 beta 与 vasp_ncl；在页面往返后保留冻结输入、服务器、节点和48核草稿。
- 模拟提交100毫秒超时：日志只有一次 submit POST，随后读取同一 `submitted-once` 记录并显示 UNKNOWN；没有自动重投。产品默认执行等待上限仍为180秒，100毫秒仅用于隔离夹具。
- 参数页直接显示模板入口，来源页可选高级来源；编辑 ENCUT 后往返保留项目草稿。配置页确认没有挂载隐藏的运行组件。

前端构建保留已有 3Dmol eval 与大 chunk 提示。没有进行长期堆内存压力测量，也没有对所有远端工具逐个做真实服务器操作。

## 后端资源路径核对

当前单任务、链、扫描的预览最终均使用 `servers.preview`，准备使用 `preview_for_prepare`，链和扫描候选池复用 `candidate_pool`，最终提交使用共同派发逻辑。明确核数、可选备注的回退在预览和最终检查均为“用户选择请求核数”，此前不一致已经修复。此次未发现需要新增验证或重写执行器才能解决的差异，因此保留现有后端合同与正在运行的批次。

实施阶段没有连接真实 SSH、提交或取消科研任务、重启正式后端、发布安装包；本次仅同步源码到 GitHub。当前源码前端刷新即可加载。最小源码差异、测试日志、页面截图、模拟请求日志及压缩验收夹具位于 `workspace-data/development-records/astra-stability-20261103/`；临时服务与测试副本在验收后清理。
