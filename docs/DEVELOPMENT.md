# 轻量开发与目录约定

先读短 `CHECKPOINT.md`，再定位要改的功能。旧长交接与 README 位于 `docs/history/`，仅按问题读取相关段落。使用 `rg` 找符号和引用，不默认打开整个后端、全部测试或所有验收文档。检查成功只记录结论与例外，不把重复长输出写进交接。

## 测试如何选择

测试数量不作为质量指标，也不作为交付目标。当前测试覆盖正常、失败、恢复和科学边界；长期回归不是运行时校验，不会因为未运行开发测试而增加用户按钮的等待。

| 改动 | 默认验证 |
|---|---|
| 文案、样式、普通表单 | 类型检查；对应页面的实际操作；不新增镜像实现用例 |
| 输入或来源 | 对应 test_inputs、test_submission_contracts、相关 Wannier 模块 |
| 调度、链、扫描、UNKNOWN | 对应 execution/recovery、chain、scans；检查准确 attempt 与不重复派发 |
| 回收和本地文件清理 | 对应 recycle/history_cleanup；核对原数据与恢复 |
| SSH、缓存、绘图 | 相关 remote/plot 模块；只对更改的路径验证请求数量和数组一致性 |
| 打包或目录整理 | 检查清单、入口、解压启动和数据排除，不重复无关业务回归 |

核心业务跨域变更或业务发布前跑一次全量回归。检查通过后，只在新增改动、失败或尚未解决的问题要求时重复。

新增测试应证明实际失败、重要合同或曾出现的缺陷；优先扩充现有领域用例。重复检查可合并，但不能仅为了减小“项数”删掉不同输入、状态或科学边界。失去对象、验证已移除功能或无断言价值的代码，经核对后归档。

## 文件去哪里

- src/、backend/：业务源码，保持现有导入路径，避免为目录外观大范围改模块。
- resources/：运行资源与内置扩展；extension-templates/：独立模板。安装校验依赖的 fixture 必须随包提供。
- tests/：长期回归与小型模拟 fixture。一次性远端验收脚本、原始计时输出放项目外的开发备份目录，交付后从活动区移出。
- packaging/：一个打包工具，共用依赖锁；macos/windows 仅放各平台启动入口与说明。
- packaging/icons/：同一个 SVG 标记及 PNG/ICO/ICNS。图标生成器仅用于开发，已生成资源直接随包使用，不增加运行依赖。
- packaging/macos/dev-launcher/：Mac 开发入口的普通源码模板。`npm run dev:launcher` 只在活动根目录生成一个应用；复制源码进行验收时不复制 `.app`。
- workspace-data/development-archives/：已完成验收的压缩备份与逐文件校验清单；development-backups/ 只保留当前工作的短回执与必要副本。完成后归档，不保留可被 Mac 索引的应用备份。
- docs/：按功能保存说明与验收，历史交接进入 history；当前 CHECKPOINT 保持短小。
- workspace-data/ 与 fpilot.local.json：机器数据与配置，不进入软件分享包。大数据、环境和 node_modules 不复制到隔离开发目录。

分享运行 ZIP。每个平台包保留完整功能，包含预构建前端；不手工选择开发文件或把项目数据库打包给使用者。需要迁移项目时单独核对本机路径、远端来源和授权归属。

整理前只备份受影响源码并核对冲突；已有大基线、科研原件与历史证据不重复复制。没有改变的前端复用其已验收构建结果。保持原正式服务和 worker 启停状态。
